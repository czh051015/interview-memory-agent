## 1. 背景与为什么改（2026-09-02 用户拍板）

- **材料顶包 bug（演示稿校准逼出，非猜的）**：SAMPLE 预置作答 v2 已把 c4 人才共育、c9 格局初成的内容**彻底删净**（按 docs/29 口径必为「没写上」），真实跑 LLM 评分仍 9 点全 hit，且 `matched_text` 引的是**材料原句**（c9 逐字、c4 去"了"改写）——作答里根本没有这些内容。证据链见 calibrate 记录。
- **机理**：judge rubric 第 1 步「作答里有没有该点核心内容」全靠 LLM 自觉；材料里有显眼对应句时 LLM 直接拿材料句顶包判 hit，连第 1 步都没执行。pydantic（judge_llm.py:30-36 Verdict）只查**枚举合法**（verdict/cause 是固定值），**不校验 matched_text 是否真的出自作答**——LLM 说什么就是什么。这就是「标准答案全部命中」的根因（不是 docs/29 口径的锅——口径只拆了"质量"，没拆"存在性"）。
- **用户三条拍板**：① 走 A 方案修引擎（prompt 加固 + 证据自洽防线，修后跑校准 + eval 回归）；② ④ 左栏要有对应标记（现状 D27 只标①）；③ 命中点（⑤）材料绿标 + 建议区给诊断理由。
- **代码侦察确认的事实**（决定改动面）：
  - hits 序列化**没透传 material_source**（shenlun.py:169-175）→ 前端 `ReconRow` hit 行 material_source 写死 null（PracticePanel.tsx:147）→ 锚点表只从 misses 构造（PracticePanel.tsx:279-288）→ ④⑤ 左栏**结构性不可能**有标记。补透传即可。

## 3. 目标结构

### 3.1 引擎修复：材料顶包（A 方案，核心语义，实现者先读）

**（1）rubric 加固（judge_llm.py:46-73 区，`_JUDGE_SYSTEM`）**

第 1 步现文「作答里有没有表达该点的核心内容（原词或同义改写都算）？完全没有 → 直接判 miss」——**加硬约束**，输出段字段注释同步改：

```
【第1步·作答检查】只允许检查 ## 作答 段。作答里有该点核心内容（原词或同义改写）→ 继续；
  完全没有 → 直接判 miss，cause=没写，两个证据填空串，跳过第2、3步。
  严禁从 ## 材料 段引用句子充当作答证据——材料句只说明"该抄什么"，不能证明"你写了什么"。

【第2步·材料支撑检查】（现文保留，补一句）支撑句必须逐字摘自材料，找不到 → 填空串，
  禁止改写/意译充当（材料顶包就是这种改写冒充）。

【输出 JSON】matched_text 字段注释改为："作答原句（逐字摘自##作答段，找不到填空串）"；
  material_source 改为："材料原句（逐字摘自##材料段，找不到填空串）"。
```

**（2）证据自洽防线（judge_llm.py 新增函数 + judge_score 收尾接入，0 token）**

新增 `_sanity_check(by_id, answer, materials, warnings)`，在 `_normalize_verdicts` 之后、构造 hits/misses 之前对每个 Verdict 执行：

```
对每个 verdict（规范化后）：
  A. verdict == "hit" 且 matched_text 非空：
     norm(matched_text) ∉ norm(answer)      # norm = 剥首尾引号/空白（含中文引号“”''）
     → 关键词复判（D40）：
        any(kw in answer for kw in 该点 keywords)
          ├─ 中 → 保留 hit：matched_text = kw 定位片段（同 _score_answer_kw 的 _matched_snippet 逻辑），
          │         matched_by = "kw"（原 "llm" 被覆盖），quality_cause 保留（④ 诊断不丢）；
          │         warnings 记 "[{id}] LLM 命中证据不在作答，已按关键词复判为 kw hit"
          └─ 不中 → 改 miss：cause = "没写"，matched_text = None，verdict = miss；
                warnings 记 "[{id}] LLM 命中证据不在作答且作答无关键词，改判 miss（疑似材料顶包）"
  B. 所有 verdict（hit/miss）material_source 非空：
     norm(material_source) ∉ norm(materials)  → 置 None
  C. 收尾统一确定性回填（D38/D28 合流）：
     材料含该点 keywords → material_source = _find_material_source(keywords, materials)
     材料不含 keywords → 保持 None（前端不标）
     （注：D28 的①回填逻辑 judge_llm.py:191-193 可并入此步统一处理，miss ②③ 的 material_source
      同样过 B/C——它们前端不高亮，但数据保持诚实）
```

- **误伤风险评估**（写给实现者，已权衡）：真·同义改写命中（fuzzy 档）时 LLM 的 matched_text 通常逐字摘自作答原句 → 不触发防线。触发防线的只有两种：顶包（材料句，作答确实没写 → kw 不中 → miss，正是期望）与 LLM 顺手 paraphrase 作答句（作答含关键词 → kw 中 → 安全兜成 kw hit）。kw 也不中的极端改写会被误杀成 miss——**接受**：传感器口径下 keywords 是拆点核心词，作答无关键词又无可回溯证据时判 miss 比假 hit 安全；回归时盯 fuzzy 指标确认损伤在噪声内（§6.3）。
- 需要 import：`_matched_snippet`（score.py，现 judge_llm.py:21 只 import 了 Point/ScoreResult/_find_material_source/_score_answer_kw）。

**风险注意（写给实现者）**：

1. **自洽防线的语义层取舍**：不做语义复判（kw 不中就 miss）——语义层会额外触发 embedding（云端 bge-m3）且顶包点作答通常真没写，语义复判结果一致还白费调用。极端同义改写被误杀的风险用 eval fuzzy 指标门禁（§6.3）。
2. **norm 规范化只剥引号 + strip**：不做分词/模糊匹配；LLM 输出带中英文引号或首尾空白要剥干净再比，否则误触发防线。c4 案例（材料句去"了"字）——去"了"后整句不在作答 → 正确触发；不要为这种 case 做"去虚词"级别的宽容，那会把顶包也放回来。
3. **④ 蓝虚线的虚线语义**：锚定位是确定性的（有 material_source 才标），虚线表达的是「参考写法（AI 诊断族）」而非「疑似位置」——与 docs/33 已砍的 fuzzy 疑似锚视觉相似但语义不同，勿在代码注释里混为一谈（防止未来有人把它当疑似锚处理）。
4. **命中诊断卡必须 0 LLM**：它只是评分证据的回放（matched_by/matched_text/material_source/quality_cause 都在 submit 响应里），点开不触发 ensureGuidance——否则每个命中行点开都烧 1 次 DeepSeek 调用，违背懒加载哲学。
5. `gold`/`current` 的锚定基与 D11 题面快照机制不变（题面改动清轮次仍生效）。

## 6. 验证

### 6.1 单测（pytest）
- 自洽防线：构造「LLM 输出 hit + matched_text=材料句」的 verdict → 断言被改 miss/cause=没写；「matched_text=作答句但作答含关键词」→ kw hit + matched_by="kw"；「作答逐字抄材料原句」→ 保持 hit（不误伤）。
- material_source 自洽：LLM 给 paraphrase → 清空 → 材料含 keywords → `_find_material_source` 回填；不含 → None。
- 序列化：practice_submit hits 带 material_source。
- 回归：docs/35 落地后原有测试全部保持绿。

## 8. 面试叙事（docs/35 §8 延伸）

> "做演示稿校准时跑出一个真 bug：作答里删净内容的点，LLM 评分仍判命中，且它给的命中证据是从材料里抄的原句——阅卷 rubric 第 1 步『作答里有没有』对 LLM 失效了，而 pydantic 校验只查枚举合法性、不查证据能不能回溯到输入。修法是两层：prompt 硬约束（matched_text 必须逐字出自作答段）+ 代码证据自洽防线（0 token）——判定 hit 的句子不在作答里，就回到关键词规则重判，关键词也没有就改判 miss。这把我项目的『LLM 输出防御』从两层扩成三层：语法层（畸形 JSON 修复）→ 语义层（pydantic 结构校验）→ 证据自洽层（输出必须能回溯到输入）。同一轮还做了命中族可视化：材料上三色标记（琥珀=没写上该抄、绿=命中句你答到了、蓝虚线=套话点参考写法），干净命中行点开给 0 LLM 的命中诊断卡（判定引擎+原句+材料句回放）——反馈从『只告诉你漏了哪』变成『逐点告诉你：这句过了、凭什么过、这句没过、差在哪』。"

## 9. Non-goals

- 不改 SCORE_ENGINE；不推翻 docs/29 传感器口径（④ 仍判 hit + 诊断标注，sanity 改的是假 hit 不是质量口径）
- ②③（答非所问/没结合材料/写模糊）左栏仍不标记（D27 维持）
- 自洽防线不做语义复判、不做模糊近似（kw 不中即 miss，风险由 eval fuzzy 门禁兜）
- 左栏命中族不加编号（D39）；无锚（material_source 空/定位失败）不做语义弱标、不复活 fuzzy_source
- 命中诊断卡 0 LLM；guidance 四分支结构不改
- 不做「作答↔材料」逐句对齐的高亮（那超漏点传感器范围，材料绿标只是该点对应句，不代表逐字比对作答）
