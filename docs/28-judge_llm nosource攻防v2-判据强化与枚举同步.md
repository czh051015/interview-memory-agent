## 0. 一句话

**上一轮 CoT 没拦住 nosource 的根因：LLM 把"具体名词罗列"（组建团队/民警代言人/现场实验）当成"具体做法展开"——判据 3 的"抽象口号"定义拦不住"报菜名"。修复：判据 3 改为"与采分点定义做完整度对比"，同时同步 pydantic 枚举（否则新 cause 被拒 = 假降级）。**

## 1. 诊断回顾（三连查实证，不是猜）

| 检查项 | 结果 | 结论 |
|---|---|---|
| 新版 prompt 已替换？ | ✅ 代码里有"套话无具体性/答非所问" | 不是替换问题 |
| pydantic cause 枚举同步？ | ❌ 仍是 `["没写","写模糊","没结合材料",""]` | **必须同步**，否则新 cause 被拒按 miss = 假降级 |
| LLM 实际判定（jiangsu nosource1） | 4/4 HIT，material_source 全真实材料句，warnings 空 | LLM 走了第 2 步，判据 1/2/4 没触发，判据 3 拦不住 |

**根因**：nosource 样本是"**具体名词罗列**"（组建团队/民警代言人/现场实验/主播连麦——菜名全报对，一道菜没做）。LLM 认为"有具体名词 = 有具体做法"——判据 3 的"加强/完善/推动等泛动词"只拦抽象口号，拦不住名词罗列。

**区分**（LLM 需要学会的）：
- 名词罗列（骨架）："组建直播团队，打造民警代言人"——没写怎么组建/怎么选人
- 做法展开（血肉）："结合实际合理选择直播地点与时间，策划情节、设置互动环节"——有主体有方式

## 2. 改动清单（只改 `src/shenlun/judge_llm.py` 两处）

### 2.1 prompt 判据 3 强化（拿金标 point 定义当"满分对照"）

完整替换 `_JUDGE_SYSTEM`：

```python
_JUDGE_SYSTEM = """你是申论阅卷人。对每个采分点，先找证据、再按证据判定；严禁先判 hit/miss 再补证据。

判定依据：题干要求 + 材料（给定资料）+ 采分点定义（point 字段为满分对照）。

对每个采分点，按三步执行：
【第1步·作答检查】作答里有没有表达该点的内容（原词或同义改写都算）？
  完全没有 → 直接判 miss，cause=没写，两个证据都填空串，跳过第2、3步。

【第2步·材料支撑检查】第1步找到的作答内容，能否在材料中找到语义支撑句？
  支撑句 = 材料中表达同一要点的原句；提出对策题可放宽：能对应到材料里的问题句/原因句也算支撑。
  找到 → 记入 material_source；找不到 → material_source 填空串。

【第3步·按证据与质量判定，从上到下依次检查，命中第一条即停】：
  1. 无材料支撑（第2步填空串）→ miss，cause=没结合材料
     （内容自创/凭空发挥；阅卷规则：答案70%源自材料，自创不得分）
  2. 内容方向与题干要求不符（如题干要求"概括举措成效"却写成"建议/对策"）→ miss，cause=答非所问
  3. 与采分点定义的完整度对比：作答是否覆盖了该点定义中的核心做法
     （主体/方式/对象/成效）？只罗列名称、没有实质展开
     （如只写"组建团队、民警代言人"，不写怎么组建/怎么选人/做成什么样）→ miss，cause=套话无具体性
     【判断技巧】把作答内容与该采分点的 point 定义逐项对照：
     作答覆盖定义不到一半、或只是定义的"标题缩写" → 按本条处理
  4. 表达模糊、意思没到位（沾边但说不清）→ miss，cause=写模糊
  5. 以上都不命中 → hit（有内容、有材料支撑、方向对、完整覆盖该点定义）

输出 JSON（每个点必须包含三步证据，只输出 JSON）：
{"verdicts": [{"point_id": "c1",
               "verdict": "hit"|"miss",
               "cause": "没写"|"写模糊"|"没结合材料"|"套话无具体性"|"答非所问"|"",
               "matched_text": "作答原句（找不到填空串）",
               "material_source": "材料支撑句（找不到填空串）"}]}"""
```

**关键改动**：判据 3 从"查抽象口号"改为"**对照 point 定义查完整度**"——LLM 手里有每个采分点的完整定义（point 字段是标准答案句），让作答内容和它比覆盖度，"报菜名"（覆盖 <50%、标题缩写）→ miss。

### 2.2 pydantic cause 枚举同步（防假降级）

```python
class Verdict(BaseModel):
    point_id: str
    verdict: Literal["hit", "miss"]
    cause: Literal["没写", "写模糊", "没结合材料", "套话无具体性", "答非所问", ""] = ""  # ← 加两个值
    matched_text: str = ""
    material_source: str = ""
```

**为什么必须先改**：不改的话，LLM 一旦真输出"套话无具体性"/"答非所问"，pydantic 校验失败 → 记 warnings → 按 miss 处理——nosource"看起来降了"其实是**误伤**，会被假数据骗。
