## 0. 一句话

评分后右栏 = **逐点对账清单**：标准答案每个采分点一行（含命中行），行首徽章标识该点状态——  
`✅ 命中` / `没写上` / `疑似方向偏离（供参考）` / `疑似脱离材料（供参考）` / `疑似表述不清（供参考）` / `已命中但套话（诊断建议）`。  
点开任一「答得不好」的行 → 建议卡给三件事：**答得不好的原因 / 跟我的答案的关系 / 改进建议**（改法 + 官方原句作参考写法）。  
锚点是**标准答案点**（它答得如何），不是用户错误（你漏了什么）。

## 1. 背景与为什么改（2026-09-02 用户拍板）

- **用户原话（方向）**：「以标准答案点为锚点，而不是以用户错误为锚点」——旧列表（docs/34：确定没写好/疑似没写好/命中折叠三区）  
  是按"用户错在哪"组织的错题视图；但产品价值在**对照标准答案逐点核**：每题 N 个点，每点什么状态一眼可见，才谈得上"哪类点反复漏"。
- **用户原话（口径）**：「错题方向统一口径：②写偏方向→疑似方向偏离（供参考）；③自创无材料→疑似脱离材料（供参考）；④踩到但宽泛→已命中但套话（诊断建议）」——  
  关键变化：②③ 在 docs/34 被归入「确定没写好」，但②（读题干判方向）③（对照材料判自创）本质是 **LLM 主观判断**（docs/28/29 实证 ③ 假阳 36%），  
  新口径把 ②③④ **全部降级为"疑似/诊断"标记**，只留 ①（没写——关键词/语义客观缺失，规则可证）为确定档。
- **三要素重写**：docs/34 的「原因 / 标准答案原文(source_snippet) / 改法」→ 用户改为「**原因 / 跟我的答案的关系 / 改进建议**」；  
  标准答案原文**并入改进建议**作「参考写法」底座（不独立成要素，后端 source_snippet 链路仍补）。
- **实现基础已具备**（代码侦察）：
  - judge_llm.py:33 `cause` 枚举已结构化：`没写 / 写模糊 / 没结合材料 / 套话无具体性 / 答非所问`（pydantic Verdict 校验）→ **五档徽章无需新判定逻辑，只做透传 + 映射**；
  - score.py Point 已有 `miss_cause` / `quality_cause` / `material_source` 字段；`_find_material_source`（score.py:154，0 token）可对 ① 补材料锚；
  - docs/34 §4 的字段透传清单全部复用。

## 3. 目标结构

### 3.1 判定 → 徽章映射（核心语义，实现者先读这段）

| 引擎 verdict | 引擎 cause（judge_llm.py:33） | 徽章文案           | 确定性定位               | 左栏材料                                      | 错题本    |
| ---------- | ------------------------- | -------------- | ------------------- | ----------------------------------------- | ------ |
| hit        | ""                        | `✅ 命中`         | —                   | 不标                                        | —      |
| hit        | 套话无具体性（④）                 | `已命中但套话（诊断建议）` | 命中确定 / 质量是 AI 诊断    | 不高亮（D27）                                  | 无（D30） |
| miss       | 没写（①）                     | `没写上`          | **确定**（客观缺失，唯一无疑似档） | 琥珀实底 + 编号（D28 补锚）                         | 有      |
| miss       | 答非所问（②）                   | `疑似方向偏离（供参考）`  | AI 判断               | 不高亮                                       | 有      |
| miss       | 没结合材料（③）                  | `疑似脱离材料（供参考）`  | AI 判断               | 不高亮                                       | 有      |
| miss       | 写模糊                       | `疑似表述不清（供参考）`  | AI 判断               | 不高亮                                       | 有      |
| miss       | （空，kw 引擎兜底）               | `没写上`          | kw 只管"关键词没出现"=没写语义  | 琥珀 + 编号（kw 下 `_find_material_source` 已有锚） | 有      |

- **kw 引擎兜底规则**：`_score_answer_kw` 不写 miss_cause → 空 cause 一律映射 `没写上`（kw 判定本质 = 关键词缺失）。
- **诚实边界**：②③④ 徽章均为 LLM 判断输出，②③ 命中假阳历史 36% → 徽章"疑似/供参考/诊断建议"就是把裁决权交还用户（产品定位落地，不是免责甩锅）。
- **徽章配色（D33）**：`没写上`=琥珀；②③④ 与写模糊（`疑似方向偏离/疑似脱离材料/疑似表述不清/已命中但套话`）=蓝；`✅ 命中`=绿。颜色语义 = **确定性分级**而非好坏分级：琥珀=规则可证（① 与左栏材料琥珀高亮同色，点行滚动定位时颜色即导航）；蓝=AI 判断层交人裁（④ 虽是 hit 仍归蓝族，与②③同属 AI 判断，hit/miss 靠徽章文字「已命中但套话」区分于真 miss）；绿=通过。形态 = 浅底深字 pill（`bg-amber-50 text-amber-800` / `bg-blue-50 text-blue-700` / `bg-emerald-50 text-emerald-700`），与现有 header 通过/命中 chips 同风格；左栏材料琥珀实底高亮不变（文本高亮需强底）。

### 3.2 右栏清单（docs/33 的"未命中列表 + 命中折叠" → 单一逐点对账列表）

```
得分点对账（6 个采分点）                    ← 按 point_order 全列
  c1 就业优先            ✅ 命中           ← 绿 chip（emerald-50），不可点不展开（D33 升级 D21）
  c2 经济韧性           没写上            ← 琥珀编号 ①（左栏有锚时点行滚动定位）
  c3 公共服务           疑似方向偏离（供参考）
  c4 民生提质           已命中但套话（诊断建议）
  c5 基层组织           疑似脱离材料（供参考）
  c6 兜底保障           ✅ 命中
```

- 行 = `[徽章] 采分点名称`；行点击展开建议卡（✅ 行不可点）。
- 徽章色（D33）：`没写上` 琥珀 · ②③④/写模糊 蓝 · `✅ 命中` 绿，浅底深字 pill；① 行琥珀编号与左栏材料高亮同色。
- 琥珀编号仅出现在 `没写上` 行且该点有 material_source（D27/D28）；编号连续 ①②③…，与左栏材料高亮一一对应。
- 默认展开第一行非 ✅（D31）。

### 3.3 建议卡（docs/34 三要素模板 → 重写为「原因 / 关系 / 建议」）

```
{徽章} {point}                               ← 行头徽章即"原因"的一句话口径
📌 为什么标
     {徽章口径句}：没写上 →「这个采分点你的作答里完全没有体现」；
     疑似方向偏离 →「AI 判断你写的内容方向与题干要求不符（供参考）」；…（按 cause 映射固定文案）
🔗 原文比对
     · 引我原句：你的作答：「{matched_text}」（空 →「你的作答中找不到与『{point}』相关的句子」）
     · 词级差异：检测到「X」，未检测到「Y、Z」（0 token 文本比对，现成 text_compare_cause）
     · 方向/支撑说明：② →「该点要求 {题干方向}，你写的是 {方向}」；③ →「该内容在材料中无支撑句，疑似自创」；④ →「只泛泛带过，未给具体主体/方式/成效」
🛠️ 改进建议：{fix}（供参考，以官方答案为准）
     · 参考写法：{source_snippet}            ← 官方原句并入此（D25），小字灰
[＋ 错题本]                                   ← 仅 ①-③ 行（D30）
```

- **原因 vs 关系的分工**：原因 = 徽章口径一句话（为什么判没写好）；关系 = 与**我的答案具体文本**的对照（引句 + 词差）——一个是判定结论，一个是证据链。
- ④ 的原因行补「（诊断建议，非漏点）」前缀，区分"没答上"与"答得不实"。
- ② 的"方向"说明需 guidance 返回（LLM 读题干判断你写偏到哪），属懒加载（点开才拉，复用现 ensureGuidance 机制）。

2. ② 的"方向说明"文本在 guidance 里生成 → 点开才拉；未点开时建议卡只显示原因徽章 + 词差 + 参考写法（matched_text 若空则"找不到相关句"）。
3. LLM 引擎下 ① material_source 补锚后可能与 `_find_material_source` 语义不一致（judge 判"没写"但材料其实含关键词）——属已知边界：判"没写"=作答没写，材料有没有是另一回事；琥珀高亮只表达"这句该抄"，不表达"你写了没"。勿在 UI 暗示"你漏抄了这句"（那要比对作答，超范围）。

## 6. 验证

1. **后端单测**：字段透传 + point_order（from_benchmark/序列化）；① 补锚（LLM 判没写 → material_source 被回填或保持空）；guidance 三分支路由（②/③/④ point → cause 语义正确）；D31 leading 语义（无，默认选前移前端）。
2. **冒烟（LLM 引擎）**：构造三类答案——①漏点答案 → `没写上` 行 + 琥珀锚 + 建议卡原因/关系/建议；②方向偏答案 → `疑似方向偏离` 徽章 + 改法为"重写方向"语义；③自创答案 → `疑似脱离材料` 徽章；④空泛答案 → `已命中但套话（诊断建议）` 行（在清单里是"命中但标记"）且无错题本按钮。
