# 升级方案：面试全流程陪伴助手

> **一句话**：把 OfferLoop 从「记得你的错题本」升级为「陪你走完一场面试的完整生命周期」——面试前帮你把简历对准 JD，面试后把战场数据存进记忆，拿到 offer 帮你算清该选哪个。

---

## 1. 现状盘点：骨架已在，缺两块增量

| 环节 | 能力 | 现状 |
|------|------|------|
| 面试前 | 错题提醒（按遗忘分层推 TopK） | ✅ 已有 |
| 面试前 | 三源模拟面试（简历 + JD + 错题） | ✅ 已有 |
| 面试前 | **简历优化** | ❌ 缺口 |
| 面试后 | 复盘入库（口语 → 结构化错题） | ✅ 已有 |
| 面试后 | **面试结果回写（挂/过/offer → 影响优先级）** | ❌ 缺口 |
| 拿 Offer | **offer 对比择优 + 谈判提示** | ❌ 缺口 |
| 底层 | 记忆引擎（掌握度 × 遗忘曲线 × 双因子） | ✅ 已有 |

**结论**：不用推倒重来。真正的增量是「简历优化」和「offer 对比」两个新模块 + 「结果回写」一个数据闭环。价值在于把它们接到已有的记忆引擎上，而不是另起炉灶。

---

## 2. 产品判断：升级的三种死法（先立规矩）

**死法一：静态化 —— 最致命。**
三环节如果做成了「简历模板工具 + 面经收集库 + offer 对比表」，OfferLoop 就退化成三个孤立静态工具，丢掉唯一的核心资产（动态遗忘内核）。**每个新模块都必须回答一个问题：它的「动态性」在哪？** 答不上来就不做。

**死法二：AI 代写简历。**
合规风险 + 面试露馅风险（简历不是你写的，追问必崩）。简历优化只做「建议 + 诊断」，永远不直接产出终稿。

**死法三：全都要。**
秋招正在进行，时间是最大约束。必须分期，先做高频刚需，低频高价值的往后放。

---

## 3. 三环节方案详解

### 3.1 面试前 · 简历优化（Now）

**用户故事**：作为投递 AI 应用开发岗的应届生，我希望在投每家公司前，系统基于目标 JD 告诉我简历该怎么调，以便我的简历和岗位要求对上，而不是用同一份简历海投。

**Why**：模拟面试已经暴露了「简历写得好但讲不出」的问题，简历是面试官提问的第一来源。同一份简历投所有岗位 = 每个岗位都少中几个关键词。而每次投递都要改简历，是秋招里**最高频**的动作。

**输入 → 输出**：

```
输入：目标 JD 文本 + 当前简历 + 错题本弱点分布 + 行为画像（已有的）
输出：一份「这家公司专属」的简历优化建议清单
```

**动态性在哪（Agent 内核，守住这条线）**：
1. **JD 变 → 重点变**：不同 JD 提取的关键词不同，建议的调整点不同（不是模板）。
2. **错题本回灌**：简历里写的技术栈，如果对应错题掌握度低（🔴 快忘了），系统标记「这条有被追问的风险」，提示要么补、要么别写太满。
3. **模拟面试反馈反向修正**：模拟面试发现「简历 STAR 写得像讲经历不讲取舍」，简历优化建议会自动带上这个毛病，下次投递提醒你改表述。
4. **行为画像联动**：历史面试被指出「表达绕弯」，简历建议里会提示把关键结论前置。

**建议输出形态**（每条建议都要能落地）：
- 关键词命中分析：JD 里出现、简历里没有的高频词（自动给出可补的表述方向）
- 风险点标注：简历里「会被追问但你掌握度低」的技术点
- 讲法提示：某条经历面试官大概率怎么问、你该怎么准备（关联错题本）

**Non-goals**：
- ❌ 不直接产出简历终稿（代写）
- ❌ 不做排版美化（那是其他工具的事）
- ❌ 不做「简历评分」玄学（分数无法归因，做了也是自嗨）

**怎么验证**：跑 3 个不同方向 JD（AI 应用 / 后端 / 客户端），人工检查每条建议是否因 JD 而异、是否引用了真实错题数据。面试官提问覆盖简历关键词的比例，作为长期指标。

**面试怎么讲**：重点讲「动态性」——这不是一个改简历工具，而是把简历当成一个**会随时间变化的对象**（JD 变、错题变、行为画像变），每次投递都是重新对焦。讲「简历是面试官提问的第一来源 → 所以简历优化和错题本是同一件事」。

---

### 3.2 面试后 · 结果回写（Next）

**用户故事**：作为面试者，我希望每场面试的最终结果（挂/过/offer）能被记住并影响后续复习优先级，以便我把精力花在真正决定成败的题目上。

**Why**：现有复盘入库只存了「题」，没存「战局」。同样是 FAIL 的题，在一家挂掉的公司里出现，和在一家进二面的公司里出现，价值完全不同。结果回写让错题本从「题库」变成「战局感知」。

**输入 → 输出**：

```
输入：面试结果（挂 / 挂但进下一轮 / offer / 主动放弃）+ 轮次 + 公司/岗位
输出：错题优先级调整 + 提醒内容变化
```

**动态性在哪**：
1. **优先级加权**：挂了之后，同类岗位高频题（比如 RAG）的提醒权重上调——下一场同类面试很可能再考。
2. **公司记忆**：同一家公司若有后续轮次，提醒自动带上「这家公司之前问过什么」。
3. **画像累计**：挂因（技术 / 表达 / 匹配度）写回行为画像，下次模拟面试定向练。

**Non-goals**：
- ❌ 不做「过/挂」的归因玄学（LLM 猜原因可以，但要标注是猜测）
- ❌ 不做公司/面经共享（涉及他人隐私，只存自己的）

**怎么验证**：造 3 组场景数据（挂了技术面 / offer 了 / 主动放弃），检查提醒排序是否按预期变化。

---

### 3.3 拿到 Offer · 对比择优（Next/Later）

**用户故事**：作为手握多个 offer 的应届生，我希望系统按我自己的择业偏好给 offer 打分对比，以便我不被单看薪资的直觉带偏，做出不后悔的决定。

**Why**：offer 决策是**低频、高情绪、不可重来**的场景。直觉决策容易事后后悔（只看了钱，忽略了成长/稳定性）。把「你更看重什么」显式化，是产品能给的真正价值——**这个功能同时也是作品集里故事性最强的一环**。

**输入 → 输出**：

```
输入：offer A/B/C 的维度数据（钱/成长/生活/风险）+ 你的偏好权重（可调）
输出：加权匹配分 + 差异分析 + 谈判要点清单
```

**动态性在哪**：
1. **偏好模型**：不是写死的评分表，是先让你显式确认权重（钱 40% / 成长 30% / 生活 20% / 风险 10%……），权重一变结果就变——这个交互本身就是「认识自己」的过程。
2. **记忆联动**：对比时自动带上「这家公司面试时暴露过什么问题」（比如某家面试时技术栈深度一般 → 成长分自动降）。
3. **谈判弹药**：基于你的错题本掌握度和市场行情，提示哪些项值得谈（base vs 期权、签字费、户口）。

**建议维度（可扩展）**：总包（base+年终+期权折现）、技术栈/业务前景、团队与导师、城市/通勤、加班强度、稳定性风险（试用期/裁员传闻）、个人目标匹配（想去大厂背书 vs 小厂空间）。

**Non-goals**：
- ❌ 不做「帮你决定」——只呈现数据和差异，决定权在你
- ❌ 不做薪资行情数据库（数据源维护成本高，可用公开信息一次性录入）

**怎么验证**：用一个虚构的 2-offer 场景跑通，人工检查打分是否随权重变化、差异分析是否抓到真实差异点。真实 offer 来了再用。

## 4. 分期路线图（为什么是这个顺序）

| 阶段 | 内容 | 为什么现在/后做 |
|------|------|----------------|
| **Now（1-2 周）** | 简历优化 | 投递是秋招最高频动作，补上「面试前」最后的缺口；且简历 + 错题本 + JD 都是已有数据，工程最小、故事最完整 |
| **Next（2-3 周）** | 结果回写 + offer 对比 | 结果回写让数据闭环完整；offer 对比是低频但高价值的「毕业动作」，放在拿到第一批 offer 前做好 |
| **Later（随时）** | 全流程驾驶舱（一次面试的完整数据流可视化） | 给面试官看的「作品集叙事」——从投递到 offer 的完整旅程图，重展示轻功能 |

**排序依据**：频率 × 价值 × 工程量。简历优化（高频 × 高价值 × 小工程）优先；offer 对比（低频 × 高价值 × 小工程）次之；驾驶舱（低频 × 展示价值 × 中工程）最后。

---

## 5. 指标体系（可衡量、可归因）

| 指标 | 定义 | 基线（目标） |
|------|------|-------------|
| 提醒复习命中率 | 提醒的 TopK 题中，面试实际被问到的比例 | 现有能力，持续跟踪（↑） |
| 简历关键词覆盖率 | 面试官提问中来自简历/JD 关键词的比例 | 升级前测一次，作为基线（↑） |
| 复盘入库及时率 | 面试后 24h 内完成复盘入库的比例 | 无基线，上线后统计 |
| offer 决策复现度 | 事后回顾，系统打分与最终选择的吻合度 | ≥ 1 次真实场景即可验证（非目标追求准确率，追求「理由清晰」） |

**诚实声明**：这类个人工具的指标不是 KPI，是「证明系统真的在工作」的证据链。给面试官讲指标时强调**可归因**（每个指标都能指到具体机制），比数字好看更重要。

---

## 6. 风险与边界

- **合规**：简历优化只出建议不出终稿；不做面经共享（个人隐私）；offer 数据仅本机存储。
- **工程现实**：三个模块全部复用现有 Chroma + LLM + 记忆引擎，不引入新依赖；前端暂不做（延续现有 CLI/脚本路线，简历优化用 markdown 输出建议即可）。
- **范围控制**：Non-goals 已写明，任何「顺手加一个」都先过「动态性在哪」这一关。
- **学习成本**：用户不是工程背景，每个模块交付时配一段「输入/输出/为什么」的口头讲解（本方案已为每模块写好），确保能自己讲出来。

## 7. 竞品客观对比（不吹自己）

| 维度 | 超级简历/职徒 | 牛客面经 | OfferShow | OfferLoop 升级版 |
|------|--------------|---------|-----------|-----------------|
| 简历 | 模板 + 评分 | - | - | JD 定向优化 + 错题联动 |
| 面经 | - | 海量题库 | - | 个人复盘 + 遗忘驱动复习 |
| Offer | - | - | 薪资行情 | 偏好加权对比 + 谈判提示 |
| **记忆贯穿** | 无 | 无 | 无 | **有（同一份记忆贯穿三环节）** |

**差异化一句话**：别人是三个环节的三个工具，OfferLoop 是**一份记忆贯穿三环节**的陪伴者——简历优化知道你的错题，offer 对比记得你面试时的判断。这不是功能多，而是**同一个"你"在不同时刻被同一套记忆服务**。
