## 1. 目标

1. **工作台前端**：左侧选项卡（工作台 / 练习 / 档案 / 录入）+ 右侧内容区，桌面 + 移动双形态。
2. **申论域 API 补齐**：把已存在但未暴露的 `practice_one` / `decide` / `score_answer` / `reflow_answer` / `diagnose` 封装成 API——**当前 /api/chat、/api/mock/* 是面试域路由，工作台不能直接复用**。
3. **闭环可演示**：打开工作台看到「今日提醒」→ 切练习 tab 开练 → 提交 → 评分 → 引导 → 回流 → 档案可见。这条链路是求职 demo 的主场景。
4. **不破坏现有形态**：`next build` 静态导出 + FastAPI 单端口托管不变；面试域页面（chat/mock-interview/items）保留不动（二期清理见 docs/19 §删留清单）。

一句话交付：**一个能点开就练的申论陪练工作台，后端 API 全部申论域化，demo 一条链路跑通。**

## 3. 工作台设计（原型已审，2026-08-29）

```
┌─────────┬──────────────────────────────────────────────┐
│ 申论陪练 │  内容区（随选项卡切换）                        │
│         │                                              │
│ ▍工作台  │  [今日提醒卡]  [角度诊断卡(by_angle)]          │
│  练习    │  [薄弱点 Top]                                │
│  档案    │                                              │
│  录入    │  ── 练习 tab ──                              │
│         │  ReAct 推题(带理由) → 作答 → 评分(命中/漏点)   │
│ 空间     │  → 逼近引导(材料位置) → 达标/上限 → 回流       │
└─────────┴──────────────────────────────────────────────┘
```

| 选项卡 | 内容 | 数据源 |
|---|---|---|
| **工作台** | 今日提醒（毕业考候选 + 该练 topK）+ 角度诊断（by_angle 条形）+ 薄弱点 Top | `/api/shenlun/remind` + `/api/diagnose` + `/api/shenlun/weakpoints` |
| **练习** | 练习会话：推题 → 作答 → 评分 → 引导（第 N 轮/上限 3）| `/api/shenlun/practice/*` |
| **档案** | 薄弱点全表（点/题型/漏次/状态），支持毕业/隔离筛选 | `/api/shenlun/weakpoints` |
| **录入** | 题目 + 标准答案 → 拆采分点 → 人审闸门 | `/api/record/decompose`（已有）|

**移动端形态**（后置 Phase 4）：底部 tab 栏（4 项），左栏收进抽屉。

## 4. 后端改造（Step A，纯新增 `app/api/shenlun.py`）

### 4.1 设计原则：无状态 API

练习会话**不做服务端 session**——前端持有会话上下文（question_id + 累计答案），每次提交全量作答，后端无状态重算。理由：静态托管前端 + 无状态后端，部署最简单；多轮逼近的"累计"是前端的事。

### 4.2 端点清单

| 端点 | 方法 | 输入 → 输出 | 实现 |
|---|---|---|---|
| `/api/shenlun/practice/start` | POST | `{}` → `{question_id, question, material, max_score, type, recommend_reason}` | `react.decide()` 推荐优先，降级题库随机（对齐 18 号 §7 冷启动降级）|
| `/api/shenlun/practice/submit` | POST | `{question_id, answer, round}` → `{hit_ratio, hits[], misses[], passed, guidance[]}` | `score_answer()` 评分；未达标且未到上限 → `_APPROACH_PROMPT` 引导；guidance 走 LLM，失败降级规则提示 |
| `/api/shenlun/practice/complete` | POST | `{question_id, answer, round, hit_ratio}` → `{ok, weak_added}` | `reflow_answer()` 回流（写 answers/weak_points/events + answer_rounds）|
| `/api/shenlun/remind` | GET | `{}` → `{graduation_candidates[], to_practice[]}` | 复用紧急度排序（miss_count × 遗忘度）+ 毕业考候选（17 号 §4.2）|
| `/api/shenlun/weakpoints` | GET | `{state?}` → `{items[]}` | `read_weak_points()` 全量（档案 tab）|

> 注意：`practice/submit` 的 guidance 仅在未达标轮次调 LLM（对齐 18 号 §4.1：达标/上限直接回流不调 LLM）；`complete` 在达标或轮次上限时由前端显式调用，避免多次 submit 重复回流。

### 4.3 复用 vs 新增

- 复用：`decide` / `score_answer` / `reflow_answer` / `read_weak_points` / `diagnose` / `_APPROACH_PROMPT` / `decompose_points` —— **零修改**
- 新增：仅 `app/api/shenlun.py` 一个文件 + `app/main.py` 挂载一行 + 可能的薄封装（如把 `decide()` 输出映射为 API 响应）

### 4.4 测试

`tests/test_shenlun_api.py`（FastAPI TestClient，mock 掉 LLM）：
1. `test_start_returns_question`：start 返回题目/材料/题型
2. `test_submit_hit_miss`：全命中作答 → `passed=true` 且 `hits` 全量
3. `test_submit_miss_gets_guidance`：漏点作答 → `passed=false` 且 `guidance` 指向漏点（mock `chat_json` 返回固定引导）
4. `test_complete_writes_reflow`：complete 后 `weak_points` 有写入
5. `test_remind_ordered`：remind 返回按紧急度排序

## 5. 前端改造（Step B）

### 5.1 页面结构（新增，不动旧页）

```
frontend/app/workbench/page.tsx     ← 工作台（左 tab + 右内容）
frontend/components/workbench/
  ├── Sidebar.tsx                   ← 左选项卡栏（工作台/练习/档案/录入）
  ├── DashboardPanel.tsx            ← 今日提醒 + 角度诊断 + 薄弱点 Top
  ├── PracticePanel.tsx             ← 练习会话（消息流 + 输入框 + 轮次状态）
  ├── ArchivePanel.tsx              ← 薄弱点全表
  └── RecordPanel.tsx               ← 录入表单（复用 /api/record/decompose）
```

`frontend/app/page.tsx` → 重定向/替换为工作台（工作台即首页）；旧 chat/mock-interview/items 页保留。

### 5.2 API 封装（`frontend/lib/api.ts` + `types.ts`）

```ts
// types.ts 新增
interface PracticeStart { question_id: string; question: string; material: string; max_score: number; type: string; recommend_reason: string }
interface PracticeSubmit { hit_ratio: number; hits: string[]; misses: string[]; passed: boolean; guidance: {point: string; hint: string}[] }
interface RemindData { graduation_candidates: {point: string; days: number}[]; to_practice: {point: string; days: number}[] }

// api.ts 新增（照抄 sendMessage 模式：fetch 相对路径 + JSON）
startPractice(), submitPractice(qid, answer, round), completePractice(qid, answer, round, hit_ratio),
getRemind(), getWeakpoints(), getDiagnose()
```

### 5.3 练习会话前端状态

```
state: { qid, question, material, rounds: [{answer, result}], roundNo, status: idle|answered|passed|finished }
```

- `status=answered`（未达标未到上限）→ 显示引导 + 输入框补充作答（round+1）
- `status=passed` 或 round 到上限 → 显示达标/汇总 + 「完成回流」→ 调 complete → 提示档案已更新
- 顶部常显 `第 N 轮 / 上限 3 轮`

## 7. 风险与规避

| 风险 | 规避 |
|---|---|
| practice/submit 反复提交导致重复回流 | complete 单独端点 + 前端显式调用；文档写清语义 |
| LLM 引导失败（guidance 挂） | 降级规则提示（「材料第 X 段有相关事例」），不阻塞评分与回流 |
| 无状态 API 丢会话 | 前端持有上下文 + 断点续练后置（对齐 18 号断点机制，Phase 4）|
| 旧页面与新工作台并存造成导航混乱 | 工作台为首页，旧页入口收进「更多」；二期清理再删 |
| 静态导出下动态路由受限 | 工作台是单页内 tab 切换，无动态路由需求 |

## 9. 面试讲点

1. **"我把 CLI 工具做成了可演示产品"**：后端函数全部已有（16/17/18 产物），这次是「API 壳 + 前端壳」——增量工程，0 重构。
2. **无状态 API 设计**：练习会话状态放前端，后端无 session——"部署最简单，多轮逼近的累计是前端的事"，被问"多用户并发"可直接答水平扩展无状态。
3. **ReAct 主动性落点**：推题带推荐理由（「你对策角度漏点最多」）——agent 内核（按遗忘状态主动提醒）第一次在产品界面可见。
4. **评分与引导分离可见**：评分是确定性传感器（标签化展示），引导是 LLM 提示（材料位置）——在 UI 上就是两种不同样式的消息，守住"可验证性 + 主动性"双叙事。
5. **移动优先画像**：底部 tab 后置立项，说明理解"在职碎片化备考"不是加分话术而是产品决策。
