## 1. 背景与用户诉求

用户复盘双模式（docs/38：trusted 题走门禁绿/黄/灰带，内联无 qid 走示证只摆差异）后提出：

> 「不想要双模式评测，想改为单模式：不管在不在题库里，都给出有没有命中得分点。只要用户给出准确答案，评分逻辑跟在题库里的题逻辑是一样的，所以不存在分离。」

**关键澄清（本轮对话已对齐）**：
- 用户要砍的是 **trusted 路由的产品分裂**（题库题有绿/黄判定、内联题只有差异配对），**不是砍防幻觉**——角色解耦、证据 0-token、灰带 LLM 永不硬判（docs/38 §0）全部保留；
- 用户拍板方案 = **单引擎 gate 三态统一判定 + 采分点来源分层决定入库资格**（L1 库题金标 / L2 用户结构化 / L3 LLM 拆解草稿）；
- L3 默认不自动入库已接受（守「记忆只记规则可证之物」护城河），用户确认后可入。

**与 docs/38 决策链的关系（写进面试叙事）**：docs/38 的双模式不是目的，是"采分点可信度"的粗糙代理——当时只有库题金标可信，所以 trusted 绑定了 question_id。本次把可信度从**路由模式**下沉为**数据属性**（points 来源标记），引擎回归统一。这是架构认知升级（可信度建模到正确位置），不是"绕回去"。

## 3. 方案一句话

**把评分引擎从「trusted 路由的双模式」收敛为「单引擎 gate 三态 + 采分点来源分层」**：所有练习请求（库内/内联）统一走三态判定（绿/黄 + 灰带 LLM 疑似），示证档退役为「无 points 可判」的兜底；判定结果是否进入记忆库由 **points 来源**决定——L1 库题金标自动回流、L2 用户手工结构化可回流、L3 LLM 拆解草稿仅展示 + 用户确认后回流；qid+内容比对保留为 L1 防伪定义。防幻觉内核与「灰带永不硬判」铁律零改动。

## 4. 方案设计

### 4.0 来源分层定义（取代 trusted 路由）

| 等级 | points 来源 | 判定 | 是否自动入 weak_points | 展示 |
|---|---|---|---|---|
| **L1** | 库题金标（benchmark 人审题 / user_questions 人审题，qid+内容比对通过 = 现 `_points_equal`）| gate 全量 | ✅ 自动（经 complete，现状不变）| 正常三色 |
| **L2** | 用户手工结构化采分点（InlineGold.points 直填，用户即人审）| gate 全量 | ✅ 可自动（信任链：用户手写点 = 人工背书）| 正常三色 |
| **L3** | LLM 从文字标答拆解（practice/parse、decompose_and_cache 产物，llm_draft 级）| gate 全量（判定照给）| ❌ 默认不入；用户一键「确认无误」后入 | 三色 + 标记「参考 · 未人工复核」|

> L2/L3 的区分信号 = 新增 `points_source` 字段（见 4.2）；**没有该字段的旧前端请求按 L2 兜底**（兼容，文档注明风险）。

### 4.1 M1 · 判定统一（后端 submit 单引擎化）

- `_resolve` 返回值去掉 trusted 路由语义；`practice_submit` **恒走 gate 分支**（gate_score → 灰带空则跳过 judge_suspect → assemble_gate），不再调 `align_answer`；
- `_mode()` / SCORE_FORCE 语义调整：SCORE_FORCE 仅保留测试锁定用途（gate/align 都可强制，生产默认 gate）；
- 前端「模式角标」删除——不再有"为什么这题有判那题没有"；
- **连带**：`get_guidance`（建议区）放行条件从 `mode == gate` 改为「L1/L2 或 L3 均可生成建议」（L3 建议加"基于未复核采分点"措辞），或按 P-D 拍板保持门禁语义。

### 4.2 M2 · 来源标记（分层信号）

- `InlineGold` 增加可选字段 `points_source: "manual" | "llm_parse"`（默认 "manual" 兼容旧前端）；
- `practice/parse`、`decompose_and_cache` 响应中带 `points_source="llm_parse"`，前端拼 InlineGold 时原样回传；
- `practice_submit` 从 req.gold.points_source 得等级：有 qid 且比对过 = L1（优先于 points_source）；否则按 points_source 分 L2/L3。

### 4.3 M3 · 内联题入库闭环（本次真正的增量）

现状缺口（现状 #4）：内联题判完漏点后**无处回流**。按用户诉求 + 记忆铁律，设计最小闭环：

```
内联题 submit（L2/L3）→ gate 判定 → 漏点展示
   └─ L2/L3 一致（P-A=② 拍板口径，2026-09-07 用户确认；本图原 L2 分支废止）：
      不入 weak_points 提醒池；漏点行带「确认无误 · 入错题本」按钮
      → 复用 docs/39 wrongbook 通道（ctx 已支持 inline_{hash}）→ 错题本第 5 页签复习
```

> ⚠️ **口径差修正记录**：本节流程图初稿写「L2：complete 扩展支持内联 qid → reflow_answer
> 直接入 weak_points」，与 P-A 拍板=②「内联一律只进错题本，不进提醒池」冲突。落地前经
> 用户确认**以拍板 ② 为准**（L2/L3 同权：漏点只进错题本），上图已按 ② 修正——
> complete 不扩展内联分支，仅库内题回流（并按 M5 带 verdicts 对齐判据）。

> ⚠️ **提醒池边界（设计约束，写死）**：内联题没有题库载体，若其弱档案点进 `weak_points` 提醒池，提醒"该练 X 点"时**没有题目可练**（死胡同）。故：
> - L3 漏点只进**错题本**（wrongbook，可单独复习），不进 weak_points 提醒池；
> - L2 进 weak_points 需连带确认该内联题是否已存 user_questions（有题载体才值得进提醒池）——见 P-A 拍板。

### 4.4 M4 · 示证档退役

- 路由层不再进 align；`align_answer` 模块**本期不删**（保留 `SCORE_FORCE=align` 测试/回归用，防回滚成本），标注 deprecated，等待 docs/37 语境完全消失后单独清；
- docs/38 D40/D48 在 CHANGES.md 标记为「被 docs/42 取代（单模式化）」。

### 4.5 M5（建议顺手修，待 P-B 拍板）· 入库判据对齐

现状 #5：reflow 用 `score_answer`（any-kw + 语义层）与展示 gate（all-kw 三态）判据不一致 → 用户看到的判定与记忆库记录的漏点可能不同。建议二选一：
- **B1（推荐，本期做）**：`reflow_answer` 新增可选参数 `verdicts`（gate 判定结果），有则按 gate 语义入库（hit = 绿 ∪ LLM 放行绿；miss = 黄；灰带 LLM 标疑似 = 记 miss 但 events 标注 suspect），无则回退现状——库内题 complete 由前端把 submit 的 verdicts 带上来，判据统一；
- **B2（延期）**：本期不动，只修 submit 单模式化；判据不一致单独立 docs 跟进（记忆库数据已有历史，切换需迁移评估）。

## 6. 验收标准

1. `practice_submit` 内联题（带 gold.points）返回 `mode="gate"` + 三色 verdicts，不再出现 `mode="align"`（SCORE_FORCE=align 除外）；
2. L3（points_source=llm_parse）判定照给且带「参考·未复核」标记位，**不自动**产生 weak_points 行；
3. L2 手动题按 P-A 拍板结果正确入库/不入库；wrongbook 内联通道（docs/39）回归通过；
4. （若 P-B=B1）库内题 complete 后 weak_points 的 hit/miss 与 submit 展示的 verdicts 一致（抽查 3 题断言）；
5. pytest 全绿（含双模式旧用例改写：align 相关用例标记 deprecated 或改 SCORE_FORCE 锁定）；快评 demo 16min→41s 不回退；
6. 前端：模式角标消失，L3 标记可见；docs/42 落地的回归报告（D50 口径不受本方案影响，另行重建）。

## 7. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 内联题无题库载体，误入提醒池 → 死胡同 | 4.3 写死边界：L3 只进错题本；P-A 建议 ② 一并规避 |
| 旧前端不带 points_source → 误判 L2（手填兜底）| 默认 manual 即 L2 语义与旧行为兼容（旧行为是不入库——⚠️ 语义变化：旧内联根本不回流，新 L2 会回流，需前端同步发版，别只改后端）|
| judge_suspect 灰带为空/LLM 挂 → 全放行（现状已有安全方向）| 保留 assemble_gate 现有 fallback，不新增 |
| reflow 判据切换（B1）污染存量记忆数据 | 只对新作答生效（verdicts 参数化，旧记录不动）；先干跑回归再上 |
| 回滚 | 路由改回 `_mode(trusted)` 一行即回双模式；CHANGES.md 留档；align_answer/SCORE_FORCE 未删 |
