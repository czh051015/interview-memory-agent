## 3. 目标布局

### 3.1 骨架（评分前 = 评分后同一两栏骨架）

```
┌────────────────────────────────────────────────────────────┐
│ header：题干摘要 · 第 N 轮 命中率 · [编辑题面] [重新评分]      │
├───────────────────────────────┬────────────────────────────┤
│ 左栏（flex 3，独立滚动）         │ 右栏（flex 2，独立滚动）         │
│ ┌ 给定材料 ────────────────┐    │ ┌ 题面配置（details 可折叠）───┐ │
│ │ 输入态：textarea          │    │ │ 题干 + 标准答案（文字/JSON） │ │
│ │ 评分态：段落只读视图，      │    │ │ + 载入示例                  │ │
│ │  应抄句 琥珀实底+编号①     │    │ └───────────────────────────┘ │
│ │  疑似句 蓝虚线（选中才现）  │    │ 评分后切换为：                │
│ └───────────────────────────┘    │ ┌ 未命中点列表 ────────────┐   │
│ ┌ 你的作答（textarea 常驻左栏）─┐   │ │ ① 民生联动（选中高亮）     │   │
│ │ 边看材料边写，评分后保留可改   │    │ ② 经济共进                │   │
│ └───────────────────────────┘    │ │ 疑 民生提质（无直接对应句） │   │
│                                   │ └───────────────────────────┘ │
│                                   │ ┌ 建议卡（选中点）─────────┐   │
│                                   │ │ 🔬文本比对/应抄原话/候选改写│   │
│                                   │ │ /参考改法/讲解/错题本      │   │
│                                   │ └───────────────────────────┘ │
│                                   │ 命中（N）折叠小字             │
└───────────────────────────────┴────────────────────────────┘
```

- **作答固定左栏**（材料下方）——"边看材料边写"是申论作答姿势，且评分前后作答不换位（线框已确认）。
- 右栏"题面配置"评分前展开（粘贴标准答案 + 评分按钮），评分后折叠成 details 让位给建议区——**但折叠的是题干/标准答案，不是评分按钮**；「重新评分」常驻 header。
- 左右栏内容高度各自独立滚动（`overflow-y-auto`），header 不滚。

### 3.2 左栏材料：段落渲染 + 锚点定位（纯前端，关键实现）

**切段**：`material.split(/\n+/)` 成段落数组；无换行（单段长文，如示例题 SAMPLE）则整体一段。

**定位 helper** `locateAnchor(material, material_source) -> {para: number, start: number, end: number} | null`：
1. 解析后端锚格式 `材料第X段：'…'` → 段号 + 引用句 `quote`（`/材料第(\d+)段：'([^']*)'/`）
2. 段内 `indexOf(quote)` 命中 → 返回 span
3. 未命中（LLM 引擎 paraphrase、或被截断）→ 全材料 `indexOf(quote)` 兜底
4. 仍无 → **判定为无锚**（返回 null）

**锚点分级（渲染规则）**：

| 状态 | 判定 | 视觉 |
|---|---|---|
| 确定锚 | `locateAnchor` 命中 | 琥珀实底 `#FAEEDA` + 行首编号徽标（深棕底白字 `①`） |
| 疑似锚 | 无锚 且 点开后 guidance 返回 `fuzzy_source` 且 cosine ≥ 0.6 | 蓝虚线框（`dashed #85B7EB` / 底 `#E6F1FB`），**无编号**，点选时才渲染 |
| 无锚灰态 | 无锚 且 疑似检索无果/embedding 不可用 | 材料上不标；右栏行 tag「无直接对应句」 |

**编号规则（D4/D6/D7）**：编号按右栏列表顺序**只分配给可定位的漏点**（① ② ③ 连续）。无锚点在右栏行首显示「疑」徽标（蓝），不占编号。疑似锚一次只联动一个（选中态），虚线锚与琥珀锚视觉永不混淆。

### 3.3 右栏：列表 + 联动 + 建议卡

- **列表行**（替代现漏点 chips）：徽标（编号/疑）+ 点名称 + 应抄句预览（`miss.material_source` 截断一行；无锚则显示 tag「无直接对应句」）。行 hover 高亮、点击选中（D3）。
- **点击联动**：`setSelected(pointId)` → 左栏 `scrollIntoView` 该锚句并加选中强调（加粗/描边）→ 未加载过 guidance 则 `ensureGuidance`（复用现懒加载）。**疑似行的点开触发 guidance 时后端现算疑似句**（D7 按需）。
- **默认态（D8）**：评分完成自动选中 `submit.leading` 并 `ensureGuidance`（与现 `score()` 里自动展开 leading 一致）。
- **建议卡内容**（= 现 PointBody 四段 + 32 降级文案，重新排布）：

```
建议 · {badge} {point}（评分后自动选中最该补时加注「最该补」）
🔬 文本比对：{guidance.cause}                        ← 32 改确定性
📄 应抄原话：{material_source}                        ← 有确定锚可点左栏定位
   或 材料疑似句：{fuzzy_source.sentence}（虚线定位，供参考）← 无锚时才出现
   或 （灰）材料中未找到直接对应句，属需自行积累的表述点
✍️ 候选改写示例（供参考，以官方答案为准）：{demo}      ← 32 降级声明
🛠️ 参考改法（供参考，以官方答案为准）：{fix}           ← 32 降级声明
[追问讲解] [＋ 错题本]                                 ← 行为不变
```

- **命中折叠行**：右栏底部小字「命中（N）：点1 / 点2 / …」（保留现 emerald chips 可展开）；`DeltaLine`「本轮新命中」保留（作答改版重评时仍有价值）。第 N 轮轨迹 `<details>` 移至右栏底部。

## 4. 后端改动

### 4.1 L4 错因 → 确定性文本比对（吸收 docs/32 §3.1，落 runtime.guidance）

- `src/mock/prompts.py`：删除 CAUSE_PROMPT 的错因诊断职责（保留文件给其它 prompt）
- `src/mock/runtime.py`（或复用 score 已有逻辑）新增：

```python
def text_compare_cause(point, answer: str) -> str:
    hit_kw = [kw for kw in point.keywords if kw in answer]
    miss_kw = [kw for kw in point.keywords if kw not in answer]
    if hit_kw:
        return f"文本比对：检测到「{'、'.join(hit_kw)}」，未检测到「{'、'.join(miss_kw)}」。"
    return f"文本比对：未检测到任何得分关键词（{'、'.join(point.keywords)}）。"
```

- guidance 内 L4 改调此函数：`cause_type="文本比对"`（字段保留、值固定，D9）、`cause=text_compare_cause(...)`、**不再调 chat_json（0 LLM token）**
- 注：LLM 判 miss 但作答实际含部分关键词时，比对如实显示"检测到 X，未检测到 Y"——正是候选证据语义，不矛盾

### 4.2 疑似锚（D6/D7）：guidance 无锚时补就近语义弱标

- `GuidanceResult`（runtime.py）增字段：
```python
fuzzy_source: dict | None = None  # {sentence: str, para: int, score: float} | None
```
- guidance 内逻辑：`material_source` 为 None（或前端判定不可定位）时：
  1. 取点描述 = `point.point + '；' + '、'.join(keywords)` 作 query
  2. 材料按 `。！？；` + 换行切句成候选集
  3. 复用评分语义层 embedding 链（**bge-m3 云端优先**，connect/read 超时已拆分；失败降级 ollama dmeta / 不可用则返回 None）——批量化候选句一次 embed
  4. top1 cosine ≥ **0.6**（常量可调）才返回 `fuzzy_source`；否则 None（宁缺毋滥）
  5. 输出 sentence 为材料原句（保证前端可 indexOf 定位），`para` = 段号
- `app/api/shenlun.py` guidance 序列化（:261 附近）加透传 `fuzzy_source`

## 7. 风险与注意（写给实现者）

1. **textarea 内不做高亮**：高亮只存在于评分后的只读段落视图；编辑态是纯 textarea——镜像层方案复杂度不值当。
2. **LLM 锚句可能是 paraphrase**：`locateAnchor` 全材料兜底仍失败 → 按无锚处理，走疑似检索；**绝不允许把定位失败的锚静默渲染成错位高亮**（高亮错句比不高亮更糟）。
3. **embedding 离线降级**：疑似检索依赖云端 bge-m3；失败走 ollama，再失败返回 None → 前端灰态，页面不报错。
4. **测试断言同步**：LLM 引擎下旧测试断言"每漏点 material_source 非空"本就该废（docs/32 已知 4 fail 根因）；随本次把断言改为"material_source 可空 + cause 以『文本比对』开头"。kw 引擎 18 用例须全绿。
5. **编号是展示层计算**，后端不参与；疑似锚永不占编号（D7）。
6. **题面改动清轮次**：防止"材料改了但旧高亮还在"的假锚。

## 10. 决策记录（面试叙事）

> "练习页的示证反馈我重构成了『候选证据 + 空间对照』：评分后左栏材料原文直接标出每个漏点该抄的原句（琥珀高亮+编号，锚定是确定性算法 0 token），右栏点哪行看哪个的建议——且建议里错因不再用 LLM 猜你『为什么漏』（那是装懂），改成确定性文本比对『检测到 X，未检测到 Y/Z』；示范和改法都标注『供参考，以官方答案为准』，分数从『最该补』上拿掉，只留候选标记。材料里锚不到的漏点，点开才做一次云端语义就近检索，标『疑似』虚线并声明它只是候选。原则：传感器给事实，诊断给候选，权威留给官方答案——也是为什么评分叫『漏点识别传感器』而不是『打分器』。"
