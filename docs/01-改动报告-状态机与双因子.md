# 改动报告：status 状态机 + 证据账本 + importance 双因子

> commit `af1a53d` · 2026-08-15 · 对应产品计划书「记忆机制」阶段的收尾补强

---

## 一、背景：为什么要改

此前记忆层有两个结构性问题，是这次改动的直接原因：

1. **`review()` 复习后只改 `mastery_score` / `review_count`，不改 `status`**——复习流转的代码根本不存在，但也没人说得清「复习到底该不该改 status」。
2. **`rank()` 的 importance 只按 `status` 查表**（fail=1.0 / partial=0.6 / pass=0.2 / unknown=0.0），导致「一道 fail 题复习到滚瓜烂熟，mastery 早已涨回 1.0，排序仍按 fail 给最高优先级，反复推你已经会的题」。

这两个问题的根子，是 **`status` 和 `mastery_score` 两个字段的职责没分清**。

---

## 二、核心设计变更

### 1. 职责分离（本次最重要的概念澄清）

| 字段 | 语义 | 时间尺度 | 被谁改 |
| --- | --- | --- | --- |
| `status` | 面试**那一刻**的表现（fail=当时没答上） | 历史事实 | 只被「首次推断 + 人工纠错」改 |
| `mastery_score` | **现在**掌握得牢不牢 | 动态状态 | 被 decay（时间）+ review（复习）改 |

结论：**复习不改 status**——复习答对改变的是「当前掌握度」，不是「你当时面试栽过」这个历史事实。

### 2. 状态机 + 证据账本

新增 `src/cleaner/state_machine.py`，只守 `status` 这一个「历史事实字段」：

- **唯一硬约束**：已判断状态（fail/partial/pass）不许退回 unknown（语义矛盾）。
- fail / partial / pass 三者之间**自由**（学习状态本来就会来回波动，不卡进步/退步）。
- 每次变更留痕，证据字段 `{time, from, to, reason, actor}`，actor ∈ `{decompose, annotate, review}`。
- `record_birth()` 记出生证据（from=null），证据链从头完整。

两个入口：
- `decompose` / 面经导入 → `record_birth()`（首次赋值）
- `annotate` 标注 → `transition()`（变更留痕 + 校验）

### 3. importance 改双因子

`rank()` 从「三元」改为「双因子」：

```
旧：score = 0.5×relevance + 0.3×status权重 + 0.2×时间衰减量
新：score = 0.5×relevance + 0.5×(status权重 × 掌握度缺口)
                          └──── 掌握度缺口 = 1 - effective_mastery
```

`掌握度缺口` 同时含「时间衰减」和「复习后 mastery 回升」两个信息，让**复习成果回流排序**。

## 四、关键决策记录（面试可讲）

### 决策 1：复习不改 status
`status` 是历史事实，复习改的是 `mastery` 连续值。两个字段两个尺度，职责分离。

### 决策 2：状态机只卡「语义矛盾」一条
硬约束只有「已判断 → unknown 拒绝」；fail↔partial↔pass 自由。状态机的价值**不是禁止，是留痕**——每次变更必须带 `reason`。

### 决策 3：删掉 recency 独立项（实现时偏离原方案）
原方案「importance = status×gap，保留 recency」在实现时发现会导致 unknown 题靠「久没复习」浮上来，破坏既有测试。根因：recency（时间衰减量）是 gap（掌握度缺口）的简化代理，两者当 mastery=1 时完全相同。故把 recency 合并进 gap，权重 0.5/0.3/0.2 → 0.5/0.5。

## 六、一句话总结（面试电梯陈述）

> 我把记忆层补成了完整的「状态层」：`status` 是历史事实、`mastery` 是当前掌握度，两者职责分离；状态机守历史事实不被乱改并留痕；排序从「静态 status + 时间」升级成「status × 掌握度缺口」，让复习成果真正回流。这个改动让系统从「记得你栽过」升级成「记得你现在还会不会」。
