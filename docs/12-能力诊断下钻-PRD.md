## 0. 背景与现状（为什么是现在、且已建了什么）

**产品 JTBD**：备考生在有限时间内清楚"每题漏了哪些采分点、哪类题型/采分点反复漏、且不遗忘，从而针对性练、练完不白练"。

**已建地基（代码可证，本 PRD 不重复造轮子）：**

| 模块 | 文件 | 已提供的能力 |
|------|------|------|
| 评分传感器 | `src/shenlun/score.py` | 输入采分点+作答 → 输出 hit/miss（确定性，可 benchmark） |
| 错题回流 | `src/shenlun/reflow.py` | 作答即入库；`weak_points` 表**以"采分点"为记忆单元**聚合 `miss_count/hit_count/state/遗忘生命周期` |
| 薄弱点档案 | `src/shenlun/profile.py` | `stats()` 已按题型(qtype)聚合薄弱分布；`weakness_snapshot()` 供 ReAct 读取；`read_weak_points()` 按紧急度排序 |
| 提醒/门面 | `run_remind.py` + `app/api/dashboard.py` | 已按 gap 分层 🔴🟡✅；`/dashboard` 已返回 stats/remind/curve |

**关键判断**：诊断的"数据骨架"已存在（`weak_points` + `stats()`）。本 PRD 要补的不是"从零搭引擎"，而是把它从**内部 dict** 升级为**用户可见、可下钻、可导出下一步动作**的产品能力。真实缺口仅两处：

1. **缺"采分点角度/类型"维度**。`weak_points` 只有 `qtype`（题型：归纳概括/综合分析…），没有 `point_type`（如 问题 / 原因 / 影响 / 对策 / 意义）。所以现在只能说"归纳概括题你弱"，说不出"你总漏'对策可行性'这种角度"——**后者才是用户真正想要的洞察**，也是区别于粉笔/SLB 的护城河表达。
2. **缺前端下钻页 + 诊断→练习闭环**。`stats()` 是给代码用的，用户看不到；且诊断结果没有回流到"推荐一道同类题练"，洞察停在"看"，没变成"练"。

## 1. Problem Statement

在职碎片化备考的用户，每次只看到"这一道题漏了哪几个点"。他不缺单题反馈，缺的是**跨题的元认知**：到底是哪一类采分角度、哪一类题型在反复拖后腿？

不知道"敌人长什么样"，练习就没有重点，时间花在已经会的点上（练完白练）——这正是 JTBD 要解决的"不遗忘、针对性练"。

**证据（现有代码可证）**：`weak_points` 已积累 point 级 miss/hit，但**没有任何聚合视图**让用户看见"我 3 道归纳概括题都漏了'对策可行性'"。`dashboard.py` 的 `hot_topics` 仍是旧面试模块的 topic，不是申论采分点，对当前产品无效。

---

## 2. Goals

- **G1（用户认知）**：用户看完诊断页，能说出"我最弱的是 X 类采分角度 / Y 类题型"。
  - 可测：诊断页下钻点击率、停留时长。
- **G2（行动闭环）**：诊断页每个薄弱点都能一键"练一道同类题"，把洞察变成练习。
  - 可测：下钻 → 练习转化率。
- **G3（护城河叙事）**：强化"记得你"的 agent 定位——跨题诊断出反复漏的薄弱类型，区别于粉笔/SLB 的 LLM 主观判分。
- **G4（技术纪律）**：诊断计算保持确定性、可 benchmark、可单测，不引入评分歧义（对齐 `score.py` 的设计哲学）。

---

## 3. Non-Goals

- ❌ 不做"好词好句 / 范文推荐"——申论按点给分，文采不加分，且偏离"客观采分点比对"护城河（之前讨论已砍）。
- ❌ 不做 AI 代写范文（永久 non-goal）。
- ❌ 不做社区 / 排行榜 / 保过承诺（永久 non-goal）。
- ❌ 不做套卷模式下的全局诊断（套卷属 Later；本期只做单题/单点维度的诊断聚合）。
- ❌ 不做外部平台 API 打通（无开放 API + 版权灰区；采集走"粘贴/截图 OCR 导入"，另立项）。

---

## 4. User Stories

- 作为在职备考用户，我想看"**哪类采分角度我反复漏**"，以便把有限时间花在真正的弱项上。
- 作为在职备考用户，我想点开一个薄弱点看"它出现在哪些题、我漏了几次、最近一次什么时候"，以便理解这个弱点。
- 作为在职备考用户，我想从诊断页直接"**练一道同类题**"，以便立刻把洞察转成练习（不白练）。
- 作为备考用户，我想看"我最近是不是在进步"（某类点的 miss→hit 转化），以便获得正反馈、调整策略。
- **空状态**：作为新用户（0 作答），我想看到"先去做几道题，诊断会自动生成"，而不是一片报错或假数据。

## 5. Requirements

### P0 — Must-Have（缺一则不叫"诊断下钻"）

**R1 采分点角度维度（数据层）**
- 在采分点模型（`score.Point` / `reflow.weak_points` 表）增加 `point_type` 字段，枚举：问题 / 原因 / 影响 / 对策 / 意义 / 其他。
- 来源：benchmark 标注时人工/模板填入（准，成本高）；或首版用 LLM 轻量分类（失败降级"未分类"，不阻塞）。
- 验收：`weak_points` 含 `point_type`；`diagnose()` 能按 `(qtype × point_type)` 二维聚合。
- 依赖：见 Open Question O1（决定 R1 实现路径，blocking）。

**R2 诊断聚合服务 `diagnose(space) -> dict`**
- 输出三层结构：`题型 → 采分角度 → 薄弱点`，每层含 `miss_count / hit_count / miss_ratio / trend / tier`。
- 确定性计算，复用 `profile.stats()` 与 `weak_points` 数据；输出纯 JSON，供前端与 ReAct 共用。
- 验收：给定 mock 的 `weak_points` 数据，`diagnose()` 返回稳定结构；单测覆盖二维聚合与空状态。

**R3 诊断页前端（Next.js app router，复用现有 `frontend/app`）**
- 总览：题型分布（哪些题型红/黄）+ **采分角度 Top 弱点**（"你最该补的是：对策可行性"）。
- 下钻：点题型 → 看该类下各采分角度的强弱；点角度 → 看代表题列表（label、漏几次、几天没练、出自哪题）。
- 空状态文案（0 作答引导）。
- 移动端可用（用户碎片化场景，优先响应式）。
- 验收：能从总览下钻到具体题；手机视口可操作。

**R4 诊断 → 练习闭环**
- 诊断页每个薄弱点提供"练同类题"入口，调用现有出题/练习（`shenlun.react` + `reflow` 出题），练完回流 `weak_points` 闭环。
- 验收：点"练一道'对策可行性'同类题" → 进入练习 → 评分 → `weak_points` 更新 → 诊断页该点数据随之变化。

### P1 — Should-Have（fast-follow）

- **R5 趋势/进步可视化**：诊断页展示某采分角度的 miss→hit 转化趋势（复用 `events` 表时间序列），给正反馈。
- **R6 诊断摘要文本**：LLM 基于诊断结构生成 2-3 句"你最该补 X，因为…"（失败降级纯统计版，对齐 `memory/profile.refine_summary` 的降级做法）。
- **R7 与提醒联动**：诊断出的"稳定弱点"自动成为 `run_remind` 的优先提醒项（已有 gap 分层，叠加 `point_type` 维度）。

### P2 — Won't-Have（this time，但架构预留）

- **R8** 跨空间/跨考试（不同省份卷）诊断对比。
- **R9** 导入（粘贴/截图 OCR）自动归类 `point_type`。

## 6. Success Metrics

**领先指标（上线后数周）**
- 诊断页周活占比
- 下钻点击率（总览 → 题型 → 角度）
- 下钻 → 练习转化率（G2 代理）

**滞后指标（数周~月）**
- 薄弱点 miss→hit 转化率（"练完不白练"的代理指标）
- 7 日留存（诊断带来的"被记住感"是否提升回访）

**目标（假设值，上线后校准）**
- 30 天内：活跃用户诊断页下钻率 ≥ 40%；下钻后练习转化率 ≥ 25%。

## 附：与现有模块的对接关系（实现参考）

```
用户作答 ──▶ score.score_answer()  ──▶ reflow.reflow_answer()  ──▶ weak_points 表
                                                            │
                                                            ▼
                                              profile.stats() / diagnose()  ──▶ /api/diagnose
                                                            │                         │
                                                            ▼                         ▼
                                                  run_remind 提醒分层        前端诊断页（下钻+练同类题）
```

**一句话交付定义**：让用户在 30 秒内回答出"我申论最该补的是哪类采分角度"，并且能从这句话直接开始练。
