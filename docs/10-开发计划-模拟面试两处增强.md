## 1. 问题一：guidance 控制流-数据流管道打通

### 1.1 现状（读盘核实，`src/mock/runtime.py`）

- `decide_next()` 已返回 `guidance`：`runtime.py:49` → `"guidance": str(data.get("guidance", ""))`
- `run_dynamic_session` 主循环**只取 `action`**：`runtime.py:300` → `next_action = decision["action"]`，`guidance` 被丢弃（仅 `reason` 在 `:302` 打印）。
- 三处现场出题的指引参数：
  - `runtime.py:241`（首题种子池空）→ 传 `""`
  - `runtime.py:243`（**deep_dive 分支**）→ 硬编码 `"深挖上一题主题"`
  - `runtime.py:247`（非 deep_dive 种子池空）→ 传 `""`
- `generate_dynamic_question()` 本身**已能消费 guidance**：`runtime.py:62` 把它塞进"出题指引"。
- prompt 侧 `_DECIDE_NEXT_PROMPT` 的 `guidance` 字段定义即"下一题方向（一段话，具体、可深挖）"（`prompts.py:31`），设计上本就是给 deep_dive 用的。

**结论**：管道两端都在，中间断了一截——`guidance` 没从 `decide_next` 流到 `generate_dynamic_question`。

### 1.2 修复设计（最小改动）

**改动 A** — 主循环取出 guidance（`runtime.py:224` 附近新增状态、`runtime.py:300` 附近赋值）：

```python
# runtime.py:224 附近，next_action 旁新增
next_action: str | None = None
next_guidance: str = ""          # 新增：决策给出的出题指引，供下轮 deep_dive 消费

# runtime.py:300 附近
next_action = decision["action"]
next_guidance = decision.get("guidance", "")   # 新增：取出题指引
if decision.get("reason"):
    print(f"      → 面试官决策：{next_action}（{decision['reason'][:60]}）")
```

**改动 B** — deep_dive 分支改用 guidance（`runtime.py:243`）：

```python
# 原
q = _mi.generate_dynamic_question(section, "深挖上一题主题", resume, jd, weak_items, asked_before)
# 改
q = _mi.generate_dynamic_question(section, next_guidance or "深挖上一题主题", resume, jd, weak_items, asked_before)
```

**生命周期安全**：`next_guidance` 在第 N 轮迭代结尾（`:300`）由 `decide_next` 算出，在第 N+1 轮顶部（`:243`）读取，与既有 `next_action` 的读写时序完全一致，无竞态、无未初始化风险（首轮 `next_guidance=""`，deep_dive 不触发于首题）。

**可选增强（不在必修范围）**：把 `_DECIDE_NEXT_PROMPT` 的 `guidance` 指令收紧为"若 action=deep_dive，则给出同主题换角度的具体深挖方向（一句话，含可追问的技术点）"，让指引更聚焦。另外 `runtime.py:247`（非 deep_dive 的种子池掏空分支）也可考虑复用 `next_guidance`，但语义上 guidance 偏 deep_dive，建议保持 `""` 不动，避免引入噪音。

### 1.3 风险 / 回滚

- 风险等级：**低**。仅新增一个字符串变量 + 替换一处硬编码串，未改控制流结构，未改 prompt 签名。
- 回滚：git revert 单文件 `src/mock/runtime.py` 即可；不影响其他模块（judge/plan/writeback 无改动）。
- 边界：`decide_next` 异常兜底返回 `guidance=""`（`runtime.py:54`），此时 `next_guidance or "深挖上一题主题"` 仍退化为硬编码串，行为不退化。

## 2. 问题二：legacy vs rubric 中间态（消融补齐）

### 2.1 现状（读盘核实，`eval/mock_interview_eval.py`）

- `run_judge` 把"金标准注入"与"prompt 选型"**绑死在一个开关**：`eval:59` → `expected_points=expected_points if use_rubric else None`，`:60` → `use_rubric=use_rubric`。
- `evaluate` 签名 `eval:77` → `def evaluate(items, *, use_rubric, cross=False, label=None)`，只透传 `use_rubric`。
- `main` 运行组合 `eval:140-145`：
  - `use_rubric=True` → D（rubric prompt + 注入金标准）← 当前"修复后"
  - `use_rubric=False, label="legacy"` → A（plain prompt + 不注入）← 当前"现状基线"
  - `cross=True` → rubric_cross（第二判官，独立模型）
- **缺失 B / C 两个中间态**：

| 模式 | use_rubric | 注入金标准 | 当前是否测 |
|---|---|---|---|
| **A** legacy | False (plain) | 否 | ✅ 测了 |
| **B** plain_inject | False (plain) | **是** | ❌ 缺 |
| **C** rubric_no_ref | True (rubric) | **否** | ❌ 缺 |
| **D** rubric | True (rubric) | 是 | ✅ 测了 |

**后果**：当前 A vs D 是"修复前后整体差距"，**不是消融**——无法分离"量规 prompt 贡献多少"与"金标准注入贡献多少"。面试被问"你的提升到底来自哪"时答不了。

### 2.2 修复设计：解耦为两个正交旋钮

**改动 A** — `run_judge` 增加独立 `inject_reference` 开关（`eval:55-63`）：

```python
def run_judge(question, answer, *, expected_points, use_rubric, inject_reference=None, cross=False):
    """inject_reference 独立开关：是否把金标准参考答案喂给阅卷人。默认跟随 use_rubric（向后兼容）。"""
    if inject_reference is None:
        inject_reference = use_rubric
    judge = judge_single_round(
        question, answer,
        expected_points=expected_points if inject_reference else None,
        use_rubric=use_rubric,
        cross=cross,
    )
    return judge.get("suggested", "partial") if _judge_ok(judge) else "partial"
```

**改动 B** — `evaluate` 透传 `inject_reference`（`eval:77-86`）：

```python
def evaluate(items, *, use_rubric, inject_reference=None, cross=False, label=None):
    ...
    judged = {
        kind: run_judge(q, it["answers"][kind], expected_points=exp,
                        use_rubric=use_rubric, inject_reference=inject_reference, cross=cross)
        for kind in ("good", "mediocre", "bad", "confident")
    }
    ...
    "judge_mode": label or _mode_label(use_rubric, inject_reference),
```

**改动 C** — 新增 `_mode_label` 映射（`eval` 顶部，紧挨 `_ORD`）：

```python
def _mode_label(use_rubric, inject_reference):
    if use_rubric and inject_reference:
        return "rubric"            # D 当前
    if use_rubric and not inject_reference:
        return "rubric_no_ref"     # C
    if not use_rubric and inject_reference:
        return "plain_inject"      # B
    return "legacy"                # A 当前 legacy
```

**改动 D** — `main` 跑四组合（`eval:140-145`）：

```python
runs = [evaluate(items, use_rubric=True, inject_reference=True)]                       # D 默认
if compare:
    runs.append(evaluate(items, use_rubric=False, inject_reference=False, label="legacy"))        # A
    runs.append(evaluate(items, use_rubric=False, inject_reference=True, label="plain_inject"))   # B
    runs.append(evaluate(items, use_rubric=True, inject_reference=False, label="rubric_no_ref"))  # C
```

**改动 E** — 打印摘要补充归因 delta（在 `main` 的打印循环后追加）：

```python
# 归因：D vs C = 量规贡献（控制注入、只变量规 prompt）
#       D vs A = 整体增益（修复前后）
_rubric = next((r for r in runs if r["judge_mode"] == "rubric"), None)
_c = next((r for r in runs if r["judge_mode"] == "rubric_no_ref"), None)
_a = next((r for r in runs if r["judge_mode"] == "legacy"), None)
if _rubric and _c:
    print(f"\n[rubric 贡献] D - C: 区分力 {_rubric['metrics']['discrimination_rate']-_c['metrics']['discrimination_rate']:+.0%}"
          f"  抗骗 {_rubric['metrics']['no_fool_rate']-_c['metrics']['no_fool_rate']:+.0%}")
if _rubric and _a:
    print(f"[整体增益] D - A: 区分力 {_rubric['metrics']['discrimination_rate']-_a['metrics']['discrimination_rate']:+.0%}"
          f"  抗骗 {_rubric['metrics']['no_fool_rate']-_a['metrics']['no_fool_rate']:+.0%}")
```

**改动 F** — 更新模块 docstring（`eval:14-16`、`:20-22`）与 `meta.note`（`eval:153-154`），标注现在为四模式消融，A/B/C/D 明确定义。

- 结构改动：仅 `eval/mock_interview_eval.py` 一处，不动 runtime / judge / 线上逻辑。
