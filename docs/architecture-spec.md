# OfferLoop 架构规格说明书（architecture-spec）

> 用途：面试讲解 + 生产级改造基线。每一节都按「输入 / 输出 / 为什么」写，目标是**你能对着这份文档讲清楚每一个模块**，而不是只会点点点。
> 立场：OfferLoop 不是一个"AI 聊天壳"，而是一个**带长期记忆、会主动提醒的面试陪练 Agent**。它的 Agent 内核 = 记忆 + 主动性（动态遗忘分层 + 自适应出题），不是功能堆砌。

---

## 0. 一句话定位

**一个"记得你"的面试错题本**：自动采集你的面试弱点，用遗忘曲线跟踪每道题的掌握度，在快忘时主动提醒，再用你的简历 + JD + 错题本出结构化模拟面试、诊断"面试为什么会崩"。

> 别人回答"市场在考什么"，OfferLoop 回答"**你现在还差什么**"。

---

## 1. 为什么它必须是 Agent（不是 CRUD 应用）

这是面试官最爱问的"灵魂问题"，先讲清楚边界：

| 能力 | 是否 Agent 内核 | 说明 |
|---|---|---|
| 记一道错题（录入/编辑/删除） | ❌ 不是 | 纯 CRUD，任何后端都能做 |
| **动态遗忘分层 + 主动提醒** | ✅ 是 | 系统**根据遗忘状态决定该提醒什么**，不是你主动来查 |
| **自适应三源模拟面试** | ✅ 是 | 出题计划随"你的简历 + JD + 当前薄弱点"动态变化 |
| 自动采集新弱点 | ✅ 是 | 面试中答差的新题自动回流错题本，越用越懂你 |

**讲法**：OfferLoop 的 Agent 价值不在"存了什么就给你什么"的静态工具，而在"**根据你的记忆状态决定该推送什么**"。记错题只是入口，真正的核心是记忆引擎 + 主动性。

---

## 2. 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│                          入口层                                │
│  CLI 脚本 (run_*.py)        │        FastAPI (app/main.py)      │
│  run_remind / run_review    │        /api/* + 托管 frontend/out │
└───────────────┬──────────────┴───────────────┬────────────────┘
                │                               │
┌───────────────▼───────────────────────────────▼────────────────┐
│                       应用 / API 层 (app/api)                    │
│  record(记错题)  items(错题本)  mock(模拟面试)  chat(标注)        │
│  dashboard(看板)  profile(简历/JD)                              │
└───────────────┬───────────────────────────────┬────────────────┘
                │                               │
┌───────────────▼──────────────┐   ┌───────────▼──────────────────┐
│      语义层 (LLM)             │   │      记忆 / 确定性层          │
│  src/llm.py (DeepSeek)        │   │  src/memory/                 │
│  decompose / plan / judge /   │   │  mastery(纯函数) knowledge_   │
│  followup / summarize         │   │  store(Chroma) embedding(Ollama)│
└───────────────┬──────────────┘   └───────────┬──────────────────┘
                │                               │
┌───────────────▼───────────────────────────────▼────────────────┐
│                        存储层                                    │
│  Chroma (本地向量库, 按 space 分 collection)  +  metadata 过滤    │
│  Ollama 本地嵌入 (shaw/dmeta-embedding-zh, 768 维)               │
└────────────────────────────────────────────────────────────────┘
```

**设计原则（最关键的一句）**：
> **LLM 只做语义活（拆解 / 出题 / 判定 / 追问），衰减 / 排序 / 状态流转全是确定性纯函数**——数字可复现、可测试，不靠 LLM 编。

这也是报告里说的"Compiler-Driven Architect > Vibe Coding"：核心逻辑是纯函数、有类型、有单测，不是让 LLM 自由发挥。

## 3. 核心数据模型：KnowledgeItem

`src/cleaner/schema.py` · pydantic v2

**输入**：一道被拆解出的面试 Q&A 记录（来自复盘录入 / 面经标注 / 模拟面试自动采集）。
**输出**：结构化错题对象，持久化进 Chroma 的 metadata。

| 字段 | 含义 | 为什么重要 |
|---|---|---|
| `question` | 题面 | 嵌入向量来源（语义检索键） |
| `answer` | 参考答案 | 来源缺失时为空；模拟面试判定会写回"面试官反馈"作为对照 |
| `status` | fail / partial / pass / unknown | 掌握度初值 + 排序重要性的依据 |
| `category` | knowledge / info | info 类不计入错题统计（避免"自我介绍"污染指标） |
| `source` | self_review / public_jingyan / mock_interview | 来源可追溯，决定"是否自动采集" |
| `mastery_score` | 0~1 | **最近一次复习时的值**；当前有效掌握度靠衰减现算 |
| `review_count` / `last_reviewed_at` | 复习次数 / 时间 | 衰减计算的锚点 |
| `space` | 记忆空间 | 多租户隔离（试玩不污染正式记忆） |
| `behavior_tags` | 行为特征 | 如"表达绕弯/回避问题"，跨次面试累积的人级画像 |
| `history` | 状态变更证据链 | `[{time,from,to,reason,actor}]`，审计用 |

**为什么用 pydantic**：类型护栏 + 自动校验；`mastery_score` 带 `ge=0.0, le=1.0` 约束，非法值直接报错而非 silently 写入。

## 4. 记忆与主动性引擎（确定性核心）

`src/memory/mastery.py` · **全部是纯函数，不碰数据库**

### 4.1 三个核心函数

| 函数 | 公式 | 输入 | 输出 | 为什么 |
|---|---|---|---|---|
| `decay` | `mastery × e^(-λt)` (λ=0.05) | 当前掌握度 + 距上次复习天数 | 衰减后掌握度 | 艾宾浩斯遗忘曲线简化；**读取时计算，不写回库** |
| `review` | `min(1.0, 上次 × 1.5)` | 答对的一道题 | 回升后的 item | 间隔重复"again"语义；答对有回报 |
| `review_fail` | `min(当前, 0.5)` | 答错的一道题 | 封顶 0.5 的 item | "以为会了其实不会"→ gap 变大、更快再出现 |
| `review_partial` | 掌握度不变，只重置复习时间 | 半对的一道题 | 仅刷新 `last_reviewed_at` | 防止把半对题误判成"快忘" |

**关键设计（必讲）**：库里存的 `mastery_score` 永远是"最近一次复习时的值"，**有效掌握度 = `decay(存储值, 距今天数)` 现算**。这样可复现、可测试、不产生"写回漂移"。

### 4.2 双因子召回排序 `rank`

```
score = relevance × 0.5 + importance × 0.5
importance = STATUS_IMPORTANCE[status] × gap     # gap = 1 - effective_mastery
```

**输入**：错题列表（可附语义相关度）。**输出**：按 `_recall_score` 降序的列表。
**为什么**：`relevance`（语义相关）保证"问什么考什么"，`importance`（状态权重 × 遗忘缺口）保证"最该复习的排第一"。复习到会的 fail 题 gap 缩小 → 自动降权，复习成果**回流排序**。

> 诚实提示：λ=0.05、权重 0.5/0.5、status 权重目前是**初值（待数据校准）**，计划书 §6 已标注。面试被问"怎么定的"时，讲"设计可校准 + 有 eval 兜底"比编一个精确数字更可信。

## 5. LLM 语义层

`src/llm.py` · DeepSeek（兼容 OpenAI SDK），`temperature=0` 保复现
- `chat(system, user)` → 文本
- `chat_json(...)` → 解析 JSON，失败重试 2 次（兼容 markdown 代码块包裹）

**只有这几处调用 LLM**（讲清"LLM 只做语义活"）：

| 调用点 | 函数 | 输入 | 输出 | 为什么必须 LLM |
|---|---|---|---|---|
| 复盘拆解 | `decompose` | 口语化复盘原文 | KnowledgeItem 列表 | 非结构化→结构化，需理解语义 |
| 面试计划 | `plan_interview` | 简历 + JD + 薄弱题池 | 章节化出题计划 | 需综合多源、生成问题 |
| 单轮判定 | `judge_single_round` | 题目 + 回答 | 期望要点/漏点/建议/判定 | 需语义比对"答到没答到" |
| 追问判断 | `judge_followup` | 题目 + 已答要点 + 本轮回答 | 是否追问 + 追问问题 | 需判断深度是否够 |
| 行为总结 | `summarize_behaviors` | 整场问答记录 | 行为特征标签 | 跨题归纳人级画像 |

**失败处理**：每一步 LLM 调用失败都有降级（如 `plan_interview` 失败→只考错题池；`summarize_behaviors` 失败→返回空数组不阻断写回）。**绝不因 LLM 抖动而半写数据**。

## 6. 两条主链路（输入 / 输出 / 为什么）

### 链路 A：记错题（采集 → 入库）
`app/api/record.py` + `src/cleaner/decompose.py`
1. **输入**：复盘文本 / 面经（支持 PDF 上传 → pypdf 提取）。
2. `decompose` → 结构化 KnowledgeItem 列表（带预览，用户确认）。
3. 去重（`dedupe_items`：批内精确 + 对库向量查重，阈值 0.93）。
4. `store_items` upsert 进 Chroma（当前 space 的 collection）。
5. **输出**：入库成功，Dashboard 立即可见。

**为什么分层**：拆解是 LLM 语义活，去重/入库是确定性活，分开才能单测、才能降级。

### 链路 B：模拟面试（自适应出题 → 判定 → 写回）
`src/mock/` 包 + `app/api/mock.py`（Web 对齐 CLI）
1. **`/mock/start`**：读 `data/resume.md` + `jd.md` + 薄弱题池 → `plan_interview` 生成章节计划（自我介绍 / 项目深挖 / 技术验证 / 行为面 / 动机面）。每题带 `section` + `source` + `item_id`（错题带 gap）。
2. **`/mock/verdict`**：每答一题 → `judge_single_round` 给 points/misses/判定；可"追问"（≤2 轮，`judge_followup`）。
3. **`/mock/complete`**：
   - weak 题 → `mastery.review/review_fail/review_partial` 写回掌握度；fail/partial 的判定写回 `answer` 作对照。
   - 非 weak 来源答差 → `_collect_new_item` **自动采集**进错题本（source=mock_interview，留痕）。
   - `summarize_behaviors` → 行为特征合并进 weak 题。
   - 全部算完**一次性 `store_items`**（失败不会半写）。
4. **输出**："已写回 N · 新采集 M" + 复盘报告（诊断"简历写得好但讲不出"这类系统性毛病）。

**为什么这是 Agent**：出题计划随你的简历/JD/薄弱点动态生成，不是固定题库；写回让记忆自我演化。

## 7. 主动性：面试前提醒

`run_remind.py` · **Agent 内核的"主动"体现**
- **输入**：fail/partial 题（按公司/岗位可选过滤）。
- `rank` 双因子排序 → 按 gap 实时分层：
  - 🔴 快忘了（gap ≥ 0.5）优先看
  - 🟡 该看看（0.2 ≤ gap < 0.5）
  - ✅ 刚看过（< 0.2）只报数量不展开
- **`--notify` 模式**：供每日定时任务调用，**只有"快忘了"的题才弹 Windows toast，否则静默**——不打扰。

**为什么"动态"**：分层不是写死清单，是每次实时按遗忘状态算出来的。这正好对应报告说的"Agent = 根据你的状态决定该提醒什么"。

## 8. 部署形态

- **CLI**：`python offerloop.py`（`--space` 切独立空间）。无外部服务依赖，本地跑。
- **Web**：`uvicorn app.main:app` 单进程，8000 端口同时托管 `/api/*` 和 `frontend/out`（Next.js 静态导出）。开发时前端可 `next dev`（3000，rewrites 代理）。
- **存储**：Chroma `PersistentClient`（落盘 `data/chroma/`）；嵌入走本地 Ollama。**面试数据不出本机**（隐私合规卖点）。

## 9. 工程化现状 vs 生产级缺口（诚实版）

对照"Demo → 生产级"路线图，**好消息是 eval 与测试已经存在**，缺口比想象小：

| 维度 | 现状（真实） | 生产级还差什么 |
|---|---|---|
| 架构/规格 | 本文件之前**无统一规格** | ✅ 本文补上 |
| 类型护栏 | pydantic 模型 + API 422 校验已落地 | 扩到全链路（配置、边界值） |
| **评估 eval** | ✅ `eval/retrieval_eval.py`（Recall@k + 阈值校准，20 标注查询）+ `eval/llm_judge_eval.py`（LLM-as-judge + 人工校准）已存在 | ❌ **缺模拟面试出题质量的 eval**（最 Agent 的部分没被量化）；无 CI 串联、无指标看板 |
| 测试 | ✅ `tests/` 约 20 模块，覆盖记忆纯函数/状态机/空间隔离/断点恢复 | 提覆盖率 + 跑通 CI |
| 持久化 | Chroma 落盘 + `migrate.py` | 缺自动备份脚本 + 迁移版本管理 |
| 部署 | 单进程 localhost | Docker 一键 + 进程守护 |
| 可观测 | LLM 调用有 debug 日志 | 无 trace/成本聚合面板 |
| MCP | 无 | 可把记忆核 + 提醒封装成 MCP server |
| 隐私叙事 | local-first 隐含 | 显式写成卖点（数据不出本机） |

**结论**：N1（规格）本文已完成；N2（eval）已完成检索+拆解，但**模拟面试出题质量 eval 是真正的空白**，也是面试最能讲的故事（"我给最 Agent 的部分也加了可量化评估"）。

## 10. 面试高频追问预案（照着练）

**Q1：掌握度衰减公式怎么来的？λ 为什么是 0.05？**
> 艾宾浩斯遗忘曲线的工程简化。λ 是初值、计划书标注待数据校准；重点是"读取时计算、不写回"的设计——保证可复现、可单测、无写回漂移。

**Q2：为什么不用 LangGraph / 多 Agent 框架？**
> 刻意不套框架。状态流转、排序、衰减都是确定性纯函数，183 个单测覆盖边界；避免把核心逻辑塞进黑盒，也更省 token、更易调试。多 Agent 是 Later 阶段——先 eval 证明单 Agent 不够再拆角色。

**Q3：为什么本地嵌入 + 云端 LLM？**
> 嵌入用本地 Ollama（shaw/dmeta-embedding-zh 768 维）：隐私（面试数据不出本机）、零 API 成本、中文适配好。LLM 推理走 DeepSeek：能力强、便宜（≈¥0.001/1K tokens）。

**Q4：冷启动怎么办（还没错题时）？**
> 面经冷启动补给（public_jingyan 来源，只有题无自评）+ 模拟面试自动采集。Web 化冷启动是已知 P1 遗留，已在路线图里。

**Q5：怎么保证检索不召回垃圾？**
> `eval/retrieval_eval.py` 用 20 条标注查询画 Recall@k + 阈值 PR 曲线，校准出相似度阈值（0.3~0.5）过滤噪音；向量查重 0.93 防重复入库。

**Q6：这是 Agent 还是普通应用？**
> 见第 1 节：记错题是 CRUD，但**动态遗忘分层 + 主动提醒 + 自适应三源模拟面试**是 Agent 内核。我们不把它包装成"全 AI"，而是讲清"哪部分必须 Agent、哪部分是工程"。

## 11. 生产级改造路线图（对齐报告）

- **Now (0-2 周)**：N1 架构规格（本文）✅ · N2 补"模拟面试出题质量 eval" + 串联 CI · N3 全链路输入校验 + 结构化日志
- **Next (2-6 周)**：X1 自动备份 + 迁移版本管理 · X2 Docker 一键部署 · X3 LLM trace / 成本看板 · X4 MCP server 暴露记忆核
- **Later (6 周+)**：L1 语音模拟面试（多模态亮点）· L2 多 Agent 协同（出题/判定/复盘，先 eval 验证）· L3 冷启动 Web 化 + 定时提醒推送

> 始终守住一条线：**动态遗忘分层 + 主动提醒**是 OfferLoop 的 Agent 灵魂，任何改造都不准把它退化成静态工具。
