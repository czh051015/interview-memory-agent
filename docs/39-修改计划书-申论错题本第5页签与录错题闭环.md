# 39 · 修改计划书：申论错题本（第 5 页签）与「录入 = 录错题」闭环

日期：2026-09-02 · 状态：待复核 → 复核后交 Claude Code 落地

## 1. 背景与用户报告的断点

原「实施计划：申论工作台三项闭环优化」落完后，用户实测发现闭环没盖好，两个断点：

1. **点「错题本」进的是面经遗留页**：申论侧没有自己的错题本，入口被旧面经导航占着。
2. **录入页只有解析、没有录错题按钮**：「录入」tab 仍是录新题进题库的形态，用户期望的「录入错题 → 进入错题本」主闭环缺一环。

用户期望（原话）：**正确的应该录入错题，然后进入错题本。**

## 6. 关键设计

### 6.1 WrongbookPanel（错题列表页）

- **数据源**：`GET /api/items?space=default&limit=200`（已按遗忘 gap 降序 = 快忘了排最前，记忆 Agent 语义天然衔接）；前端过滤 `reflow_tier` 非空（schema L55「空 = 非申论条目」，面经条目自动滤掉）。
- **行展示字段映射**（对 build_wrongbook_item 落库结果）：

| 条目字段 | 展示 |
|---|---|
| `question` | 题干 |
| `topic` | 漏点名（采分点原文）+ `point_id` 徽标 |
| `answer` | 我的作答（片段/空答） |
| `material_source` | 漏点材料锚定（L3） |
| `feedback` | 错因（【错因】cause_type：cause）+ 示范（【示范】demo） |
| `reflow_tier` / `status` | 红档标识（初始红，docs/22） |

- **行操作**：删除 `DELETE /api/items/{id}?space=default`（现成，空间隔离校验）。
- **空态**：两引导按钮「去练习」「录错题」（走父级 tab 回调）。
- **定位**：接收 `highlightKey`，滚动高亮对应条目（供档案行「错题 →」落点用）。

### 6.2 错因三档快选（前端标签 → 提交枚举映射）

| 前端标签（用户拍板） | 提交 `cause_type`（后端枚举，shenlun.py L341） |
|---|---|
| 没写上 | 完全没提 |
| 太宽泛 | 太模糊 |
| 写偏 | 写偏 |

### 6.3 RecordPanel「录错题」流（默认 mode）

1. 粘贴题面（题干）+ 标准答案 → 可选「LLM 拆点预览」（复用现有录新题的拆解预览链路，产物即采分点列表）。
2. 填「我的作答」（`answer`）。
3. 拆点结果逐点勾选「这道题我漏了」→ 每漏点快选错因（§6.2）。
4. 对每个漏点提交一次 `POST /shenlun/wrongbook`（**每漏点一条，前端循环**）：

```
body = {
  gold: { question, qtype, material, points },   // 单题模式（_resolve L163-168 自动合成）
  point_id,                                       // 勾选的漏点
  answer,                                         // 我的作答全文（服务端用它重算材料锚）
  cause_type,                                     // 映射后的枚举值
  cause: "",                                      // 可空（快选即够）
}
```

5. 全部成功后 toast + 「去错题本看」→ `onDone` 回调切 wrongbook tab。

> 注意：单题模式 `gold.question` **必填**——_resolve 会把它合成为错题条目题干，空则条目题干为空（§7 风险 2）。「录新题进题库」保留为 mode 2，交互与落库逻辑不动（wrongbook.py L5 ⚠️：录入预览 shenlun_record 只预览不落库，勿混淆）。

## 7. 风险与注意

1. **⚠️ 单题条目 id 冲突（建议随本改动一并修）**：wrongbook.py L40 `id = sl_{ctx.id}_{point_id}`；单题模式 ctx.id 恒 `"inline"`（_resolve L167）→ 手动录两道不同题若都漏 c1，后一条会**覆盖**前一条（题面丢失）。最小修法：_resolve L167 改为 `ctx = {"id": f"inline_{md5(question)[:8]}", ...}`（同题同点仍覆盖 = 保留 upsert 语义；跨题不再冲突）。落地前 grep `ctx["id"]` 确认无其他消费点（ctx 目前只被错题本落库消费）。
2. **单题模式题干必填**：gold.question 为空 → 错题条目 question 为空串（build_wrongbook_item 直接取 `question_item["task"]["question"]`），前端表单校验兜底。
3. **id 稳定 = upsert 覆盖**：同题同漏点重复回流/录入会覆盖旧条目（含旧错因）——设计如此（docs/22），非 bug，错题本 UI 无需去重。
4. **`frontend/out/` 是构建产物**：源码改完需 `npm run build` 才能在静态部署看到；开发态直接 `npm run dev`。
5. **跨面板跳转走 props 回调**（先例 onGoPractice），勿引入新路由/query 参数，保持 SPA state 单一来源。
