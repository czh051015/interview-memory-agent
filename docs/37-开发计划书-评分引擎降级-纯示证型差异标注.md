## 0. TL;DR

评分引擎从「判定型」（LLM 判 hit/miss/套话，输出对错结论）降级为「配对型」（只做**可回溯的文本配对**：作答句 ↔ 标准答案要点，输出相似/不相似 + 共现词 + 相似度，**不输出任何好坏结论**）。

- 动机：LLM 阅卷出现「材料顶包」（作答没写的内容，LLM 从材料借句证明命中）与证据伪造，判定层可信度不可修复地受损。与其在判定上继续打补丁，不如**让判定从结构上消失**——没有生成就没有幻觉。
- 产品定位回到最初定义：**AI 标注差异，你自己判断要不要补**。判定权完整交还用户。
- 已验证：`eval/probe_align.py` 纯词重叠（0 token）即可干净标出「作答中未写到的采分点」（demo 中 c4/c9 一秒标出），且输出全部可逐字复核。
- 判定退役连带：五档徽章、命中诊断卡、LLM 建议生成（guidance）全部退役；错题本从「AI 自动判」回归「用户自标」（与 interview 错题本原形态一致）。

**降级判断**：与其继续修 LLM，不如把它从判据链里整个拿掉。申论要点复述的本质是「你的句子 ↔ 该写什么的句子」的对应关系——这是**文本配对**，不需要主观判断，规则可做；而「这句算不算写到了」「写得好不好」是主观裁决，本该属于人。

## 2. 路线定案：纯示证型

### 2.1 系统做什么 / 不做什么

| | 做（配对层） | 不做（判定层，退役） |
|---|---|---|
| 输入 | 材料原文、用户作答、标准答案（拆点结果） | — |
| 处理 | ① 作答按句切分（规则）② 每句与标准答案要点做配对 ③ 无配对的点/句标为「候选」 | ❌ 判 hit/miss/漏答/宽泛/套话 ❌ 输出三色分级 ❌ 生成「你应该怎么改」的建议文本 ❌ 自动统计「漏了 N 个点」 |
| 输出 | 配对（句↔点 + 共现词 + 相似度）、未见对应（候选）、无对应句（候选） | — |
| 下游 | 错题本改为**用户自标**（用户看了配对自行判断后点击入库） | ❌ AI 自动判错题 |

### 2.2 为什么顶包/伪造结构性消失

配对层的所有输出 = 引原文 + 数字：
- 「共现词」= keywords 在作答句里的子串命中，可逐字复核；
- 「相似度」= 词重叠或 embedding cosine，确定算法；
- 没有任何 LLM 自由生成的句子 → **没有可以伪造的证据字段** → 材料顶包在结构上不可能发生。

### 2.3 措辞总则（UI/文案/接口注释统一遵守）

所有文案把「判定」翻译成「观察」，命中以下**禁止词表**的表述一律不得出现：

```
禁止：漏答 / 命中 / 没写上 / 答非所问 / 偏离 / 脱离材料 / 套话 / 宽泛 / 表述不清 / 建议你补 / 你应该写
允许：未见对应句（候选）/ 有对应 / 共现词：… / 相似度 0.62 / 该句与所有要点均无明显对应（候选）/
      是否重要、要不要补由你判断
```

「未见对应」≠「你漏了」——它只是陈述「作答中没有包含该要点关键词的句子」这一可复核事实，是否构成需要补的差异由用户裁决。

## 5. 配对层设计（align.py）

### 5.1 切句（规则，0 token）

```
split_sentences(text):
  按 [。；!?！？\n] 切分 → 去掉长度 < 6 的碎片 → 返回语义分句列表
  （demo 实测：v2 作答 350 字切出 8 句，基本对应「举措四条/成效三条/总起一句」结构）
```

### 5.2 逐点 kw 配对（主证据，0 token）

对每个采分点 p（id/point/keywords/官方原句 source_snippet?）：

```
p 的每个 keyword k（子串）出现在作答句 c_i 中？
  → 记录 alignment{point_id, chunk_id, kws_hit:[k...], method:"kw"}
一个点可配多个句、一个句可配多个点 —— 串点如实呈现（如 c1「互通」串到服务共享句），
属于候选噪声，由用户判断，不做消歧。
```

要点文本（弱配对用）：`p.point + 官方原句(若有) + keywords`。

### 5.3 embedding 语义弱配对（第二路，可选）

只对 **kw 零命中的点**（gap 候选）做，控制调用次数（每 gap 点 ≤ 1 次）：

```
对每个 gap 点：
  q_emb = embed(要点文本)             # bge-m3 云端 / dmeta 本地，复用 embed_api
  每句 c_i 的 sim_i = cosine(q_emb, embed(c_i))
  best = max(sim_i)
  best ≥ τ(默认 0.60，实现处可调常量) → 记 alignment{..., method:"semantic", similarity:best}
                                   → 从 gaps 移除，前端呈现为「~语义弱对应句X」
  best < τ                          → 保持 gap，附 max_similarity 数字（如 0.31）
embedding 异常/不可用 → 跳过，纯 kw 结果照常返回（弱配对缺失可接受，不阻塞）
```

> 阈值 τ=0.60 沿用此前 fuzzy 疑似锚经验值；落地后如需校准，改 `align.py` 顶部常量即可，不动接口。

### 5.4 材料出处段（展示辅助，不参与判据）

每点用确定性方法（关键词在材料中的位置，复用 `_find_material_source` 思路）找含该点关键词的材料句，作为「出处附注」随点返回；找不到 → 标注「该点非直接摘抄，需自行概括」（陈述事实，非判定）。此字段仅供三要素展示（材料原文 ↔ 答案要点对照），**不进配对链**（配对只发生在作答↔要点）。

## 6. 对齐接口契约

`practice_submit` 请求不变（answer/points/material/question）；**响应结构整体替换**（前端 types.ts 同步）：

```jsonc
{
  "official_points": [   // 展示锚：标准答案逐点（右栏列表数据源）
    { "id": "c1", "point": "设施互通", "keywords": ["城际公交","高速免费","道路","互通"],
      "official_sentence": "两地开通城际公交…",   // source_snippet，可空
      "material_ref": "给定资料第3段「…城际公交…」" }   // 出处附注，可空
  ],
  "answer_chunks": [ { "id": 1, "text": "A区与B县地域相连…" } ],  // 切句结果
  "alignments": [   // 配对（有对应）
    { "point_id": "c1", "chunk_id": 2, "kws_hit": ["城际公交","道路","互通"], "method": "kw" },
    { "point_id": "c4", "chunk_id": 7, "similarity": 0.62, "method": "semantic" }   // 弱对应示例
  ],
  "gaps": [ { "point_id": "c4", "max_similarity": 0.31 } ],  // 无 kw、无语义弱对应 → 未见对应候选
  "orphans": [ { "chunk_id": 1, "max_similarity": 0.22 } ],  // 作答句无任何对应 → 无对应候选
  "meta": { "engine": "align", "semantic_used": false, "warnings": [] }
}
```

语义：
- `alignments` 中 `method:"kw"` → 前端标「◎ 有对应」，展开显示共现词；
- `method:"semantic"` → 前端标「~ 语义弱对应 0.62」；
- `gaps` → 「○ 未见对应句（候选）」——**措辞不得出现「漏答/没写上」**；
- `orphans` → 「该句与所有要点均无明显对应（候选）」——语义 = 作答里写了但没对到答案结构的内容（自创/延伸候选），是否重要由用户判断。

历史字段（hit_ids/miss_ids/hit_points/miss_points/quality_cause/miss_cause/leading）**全部移除**；若前端/API 其他调用方引用，同步清理。

## 7. 前端对照视图（PracticePanel.tsx 重构）

### 7.1 布局

评分前保持 docs/33 骨架（左材料/作答 textarea，右题面配置 + 评分按钮）。评分后右栏切为「对照视图」：

```
┌────────────────────────────────┬─────────────────────────────────┐
│ 左栏（宽）                      │ 右栏（标准答案逐点对账）          │
│ ┌ 材料原文（分段只读）─────────┐ │ ┌ 第1点 设施互通 ─────────────┐  │
│ │  …该段的句子…               │ │ │ 官方原句：两地开通城际公交…  │  │
│ └─────────────────────────────┘ │ │ ◎ 对应作答句2  共现:城际公交│  │
│ ┌ 你的作答（切句展示）─────────┐ │ │   道路 互通                │  │
│ │ ① A区与B县地域相连…（○ 无对应候选）│ └────────────────────────────┘  │
│ │ ② 举措方面：一是设施互通…（◎→点1）│ ┌ 第4点 人才共育 ─────────────┐  │
│ │ ③ …                         │ │ │ 官方原句：干部互派挂职机制… │  │
│ └─────────────────────────────┘ │ │ ○ 未见对应句（候选）        │  │
│  （点左栏句 ↔ 自动定位右栏点；      │ │    （语义最近句相似度 0.31） │  │
│    点右栏点 ↔ 滚动左栏对应句）     │ └────────────────────────────┘  │
│  图例：◎有对应  ○未见对应  ~弱对应  │ …                             │
└────────────────────────────────┴─────────────────────────────────┘
```

### 7.2 交互

- 点右栏某点 → 左栏滚动到对应作答句（kw/semantic 配对），并高亮该句共现词（中性底纹，非红绿语义色）；点「○ 未见对应」行 → 左栏不滚动，行内展示语义最近句相似度数字（如有）。
- 点左栏某作答句 → 右栏高亮与其配对的所有点（一个句配多个点如实展示）。
- 题面/作答改动 → 清空对照轮次（同 docs/33 既有规则）。

### 7.3 文案模板（实现直接照抄）

```
第 {id} 点 · {point}
  官方原句：{official_sentence 或 “（未提供官方原句）”}
  材料出处：{material_ref 或 “该点无直接材料出处（需自行概括）”}
  你的作答：{method==kw  →  “作答句 {n} 含关键词 {共现词}”  
             method==semantic → “作答句 {n} 语义相近（相似度 {s}），无关键词重叠”
             gap →  “作答中未见包含该点关键词的句子（候选：请自行判断是否重要、要不要补）”
             }
```

## 10. 验收标准

1. **0 成本复跑**：`eval/probe_align.py` 输出与 demo 一致（c4/c9 等 4 点零 kw 命中 → gap；5 点有配对；句1 孤儿）。此条为纯规则回归锚，前端不依赖 LLM。
2. **判定链路断连**：Grep 确认评分链路无 `judge_score`/`SCORE_ENGINE=="llm"` 的运行时路径；`config.py` 无 llm 开关。
3. **禁止词零残留**：前端对照视图文案不含 §2.3 禁止词（Grep 抽查：漏答/套话/命中/没写上/建议你补…）。
4. **演示路径**：前端起服 → 硬刷新 → 载入示例题（作答自动预填 v2）→ 点「对照」→ 预期：
   - 右栏 9 点：c1/c2/c3/c6/c8 显示「◎ 对应作答句…」；c4/c5/c7/c9 显示「○ 未见对应句（候选）」；c8 同时显示句5（就业）与句8（幸福感）两个配对（串点如实）；
   - 左栏作答 8 句：句1 标「无对应（候选）」，句2-8 各标对应点；
   - 每个「◎」展开可见共现词；「○」可见语义最近句相似度数字（若 embedding 可用）。
5. **错题本自标**：对照视图提供「标记此题」入口 → 入库成功，无判定字段依赖。
6. **三要素齐全**：左栏材料原文可读、作答逐句可读；右栏每点含 官方原句（或占位）+ 材料出处（或占位）。

## 11. Non-goals & 强模式预留

- **不做**：任何好坏判定（hit/miss/漏答/宽泛/套话）、三色分级、自动「漏了 N 点」统计、LLM 生成改进建议、材料顶包防线的补丁式修复（结构性消除，无需防线）。
- **不强删**：judge_llm.py / guidance / eval 套件保留原样（git 历史 + 强模式预留），仅断连调用链 + 注释标注。
- **强模式（将来可选）**：若 LLM 判定质量提升或有可靠测评手段，可在配对结果之上重建判定层——align 输出作为其「结构化输入」恰好是干净底座（这正是降级的架构红利：判定层与配对层解耦）。
- **本改动不做 eval 回归**：评分评测（demo_eval/compare_engines/medium_eval）测的是判定指标，判定退役后无意义；如需给 Claude 演示「评估纪律」，跑单测即可。

## 12. 风险与开放问题（实现者注意，不阻塞）

1. **串点噪声**：一词配多点（demo 已见）会如实展示，可能让对照视图显乱——一期接受（候选语义），不做消歧；若体验差，二期可按「句内该点名称词优先」加权。
2. **官方原句缺失**：手写 points（SAMPLE/前端内联）无 source_snippet，配对靠 keywords 够用，但展示缺「官方原句」一栏——占位文案已定（§7.3），不阻塞。
3. **embedding 依赖**：semantic 弱配对依赖网络/模型可用性；异常即降级纯 kw，gap 数量会偏多（同义改写会被标「未见对应」）——诚实语义下可接受，`meta.semantic_used` 供前端提示「语义比对不可用」。
4. **τ 阈值**：0.60 为经验值，可能过严/过松；落地后可用 probe_align.py 加 semantic 开关实测校准，改动仅在 align.py 常量。
5. **演示叙事变化**：系统从「AI 判你漏了」变「AI 标出未见对应、你判断」——演示稿话术由用户定，本计划书不代拟。
