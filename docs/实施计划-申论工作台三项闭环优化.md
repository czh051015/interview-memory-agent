## 二、任务一：录入页补落库闭环（方案 A）

### 目标
录入页从"只读演示"变成完整闭环：拆解预览 → 逐点编辑（改分/改词/删点/加点）→ 确认入库 → 题目进题库（可被练习/推题使用）。

### 设计

**1. 入库逻辑从 CLI 抽成可复用模块（防两份实现漂移）**

新建 `src/shenlun/question_store.py`，把 `scripts/run_decompose_question.py` 里的 `_next_question_id`（L42-49）与 `_save_user_question`（L95-130）逻辑搬进来，接口：

```python
def next_user_question_id() -> str: ...        # user_YYYYMMDD_NN，按当天已入库递增
def save_user_question(*, question_id, question, requirements, material,
                       max_score, points: list[dict]) -> Path: ...
```

- `points` 每项 `{id, point, keywords, score, point_type}`，写库时统一补 `approved: True, source: "human_approved"`（与 CLI 人审通过后一致，防循环论证语义：**页面点"确认入库" = 全部点人工通过**，等价于 `annotate_points` 全 k）。
- doc 结构与 CLI 逐字段一致（meta.authority="user"，task/gold 布局同 `_save_user_question`）。
- **CLI 改为 import 该模块**（删除自身两份函数），行为不变，仍可单独跑。

**2. 新端点 `POST /api/shenlun/questions`**（shenlun.py 新增）

请求体（Pydantic）：

```
question: str            # 题干
requirements: str = ""
material: str = ""       # 给定材料
max_score: int = 20
points: list[{id, point, keywords, score, point_type}]   # 前端编辑后的最终采分点
```

服务端行为：
- 校验：points 非空；每个点 point 非空、score >= 0；max_score >= 1。
- `question_id = next_user_question_id()`（支持可选入参覆盖，供 CLI/测试注入）。
- `save_user_question(...)` → 返回 `{question_id, stored: len(points)}`。
- 不调 LLM（纯写库，快）。

**3. 前端 RecordPanel 预览区改可编辑 + 确认入库**

- 预览每个点渲染为可编辑行：point 文本框、score 数字框、keywords 文本框（逗号分隔）、删除按钮。
- 底部"＋ 添加采分点"（空点行，用户自填，入库前校验非空）。
- 顶部"满分"沿用表单 max_score。
- 按钮"确认入库"→ `POST /api/shenlun/questions` → 成功提示"已入库：{question_id}（可去「练习」tab 推题）"并清空表单；失败展示错误。
- notice 文案（L55-59）从"demo 版仅预览"改为"拆出 N 个点——可直接编辑分值/关键词，确认后入库"。

|---|---|---|
| `src/shenlun/question_store.py` | 新增 | 入库逻辑唯一实现 |

## 三、任务二：档案页跳到具体错题

### 目标
档案页弱项行可点击 → 跳到错题本并**定位到该弱项对应的具体错题条目**（含题干/你的作答/漏点材料锚定/错因与示范）。

### 设计

关联链已天然存在：档案行 `question_id` + `point_id`（point_key 拆开）→ 错题条目 id = `sl_{question_id}_{point_id}`。

**1. ArchivePanel 行尾加"错题 →"入口**
- 仅当该弱项可能有过错题时才有意义——不做预查询（省一次请求），点击即跳，由目标页处理"找不到"。
- 点击 → `router.push("/items?item=sl_{question_id}_{point_id}&ref=weakpoint")`。

**2. items 页（错题本列表）支持定位参数**
- `useEffect` 读 `searchParams.item`：存在时 `setTab("")`（全部）+ `fetchItems({status:"", space, limit:300})`（全量，条目被标过 pass/partial 也能找到）。
- 找到 `it.id === item` 的条目：`scrollIntoView` + 临时高亮（ring 边框 3 秒），自动展开 answer 折叠区。
- 找不到：顶部提示"该弱项尚未入错题本（漏答点加入错题本后才会出现）"。
- 非定位参数进入时行为与现在完全一致（默认 fail tab）——定位是叠加不改变原逻辑。

**3. items 页对申论错题条目的增强展示（关键，否则跳到的是"看不懂的面试条目"）**
- 判定：`it.reflow_tier` 非空（错题条目初始 "red"，`wrongbook.py` L53）即为申论条目。
- 展示追加：`[申论 · {reflow_tier}]` 小标签；`material_source`（漏点材料锚定）；`feedback`（错因+示范）；topic 已是漏点名会自动显示。
- `KnowledgeItem` 前端类型（types.ts L17-40）补申论字段：`question_id / point_id / material_source / demo_text / reflow_tier / feedback`（后端 pydantic 已序列化，纯前端类型补齐）。

后端零改动（复用 `/api/items`）。

## 四、任务三：练习页示例题文字版（方案 A）

### 必须先点破的技术冲突（本任务核心决策）

示例题声明了 `question_id = "henan_2025_city_1"`（SAMPLE L32）→ 评分走**门禁模式**，依赖 D41 校验：内联采分点必须与库题逐点全量一致（shenlun.py `_points_equal` L115-134），不一致 → 400 且前端清 trustQid 掉回示证（PracticePanel L350-354）。

**如果示例题改走"文字解析链路"**：`parsePractice` 拆出的点 ≠ 库题点（LLM 拆点有漂移，不可能逐字命中 9 点的 id/point/keywords）→ **必然 400 → 门禁演示丢失**。因此"载入即文字解析 + 门禁三色"二者不可兼得。

**决策：载入示例题显示文字版标准答案（解决"界面是 JSON"的原始诉求），评分仍提交库题结构化快照（保住门禁稳定演示）；用户改动文字/题面 → 自动回示证（走真实文字解析）**。

- 这一设计同时是"真实用户体验"的准确表达：门禁题的正确答案本来就来自题库，不是靠贴文字现拆；贴文字现拆 → 无库题声明 → 示证模式，两条路径各自成立，D41 防伪零让步。
- 附带收益：示例题评分不再每次调 LLM parse（省 token、无解析失败分支）。

### 设计

**1. SAMPLE 增加文字版标准答案**
```ts
standard_answer_text: string   // 纯文字，像考生/官方参考答案的写法，不是 JSON 摊平
```
草稿（基于库题 9 点，关键词与库题保持一致，可直接用/微调）：
> 举措方面：一是设施互通。两地开通城际公交，实现高速公路免费互通，并规划新建、提升改造 3 条道路。二是产业协同。在 A 区新兴产业带动下，一批新能源项目相继落地 B 县，双方共建综合货运枢纽，形成面膜上下游供应链生态圈。三是服务共享。推动医疗、文旅等资源互通，联合开展美食文创街区等旅游营销活动。四是人才共育。签署人才协同发展战略合作框架协议，建立年轻干部互派挂职机制。五是民生联动。推广"找零工"App 促进灵活就业，吸引 A 区市民赴 B 县置业。成效方面：一是经济共进。A 区 GDP 增幅达 31%，B 县制造业投资增速位列全市第一，两地增速差距由 1.6 个百分点缩小到 1.1 个百分点。二是产业升级。B 县二三产业协同驱动的经济增长方式逐渐形成。三是民生提质。两地群众就医、消费、就业更加便利，获得感、幸福感增强。四是格局初成。"1+1>2"的区域发展格局初步形成。

**2. loadSample 改动**
- `setPointsStr(SAMPLE.standard_answer_text)`（不再 JSON.stringify）。
- 新增 state `samplePoints`（或复用常量判断）：载入时存 `SAMPLE.points`。

**3. resolveGold 加"库题捷径分支"**（唯一逻辑改动点，L267-313）
- 在 `JSON.parse` 尝试**之前**：若 `trustQid` 非空（载入后题面未被动过）→ 直接返回 `{question_id: trustQid, question: questionStr, material: materialStr, points: samplePoints}`，跳过解析。
- 用户改文字/题面 → `touchConfig` 已清 trustQid → 落入现有逻辑（非 JSON → parsePractice → 示证），行为不变。
- 其余（configChanged/lastUsed/编辑态）不受影响：lastUsed.points 记录的是文字串，改文字即 configChanged，语义正确。

**4. UI 细节（小）**
- "标准答案（文字或 JSON）" label/placeholder 不变（JSON 手填能力保留给高级用户）。
