## Part 1 · 六个疑点逐一解答

### 疑点 1：187 个单元测试是真实数据吗？测试效果是真的很好吗？你用什么体现的？

**事实（已实测）：**
- `grep def test_` 数出 187 个测试函数，`pytest` 实测 **187 passed in 2.65s**（README 里写的 183 已过时，回答时要说 187）。
- 覆盖范围（从测试文件名 + mock 情况看）：衰减边界、双因子排序回流、状态机约束、幂等写回、面试循环逻辑（`test_mock_interview.py` 里 LLM 全部 `@patch` mock 掉）。
- 真正的"效果证据"只有两个 eval：
  - `eval/retrieval_eval_results.json`：387 条数据、**20 条人工标注查询**，Recall@5=0.704、Precision@5=0.36、噪音归零（k≤9 时 total_noise=0），阈值 0.45 由 PR 曲线校准。
  - `eval/llm_judge_eval_results.json`：**1 份面试记录**拆出 27 题，打标 category 准确率 0.963（人工校准 4 条后，LLM judge 漏判 2 条）。

**诚实结论：** 187 个测试证明的是"**确定性机制按规格工作**"（衰减/排序/状态机/幂等），不是"产品效果好"。语义层（拆解/打标/出题/追问）证据很薄——检索 eval 只有 20 条查询、打标 eval 只有 1 份样本。**Agent 层（模拟面试出题质量）零量化，这正是你标的缺口。**

**面试讲法（分层证据，诚实边界）：**
> "我有三层证据：① 机制层——187 个单元测试全绿，覆盖衰减边界、排序回流、状态机、幂等写回；② 语义层——检索 Recall@5=0.704（20 条人工标注查询）、打标准确率 0.963，样本小但我如实标注了；③ Agent 层——出题质量我承认还没量化，所以设计了判别 eval（用固定量规 + 好坏答案样本证明阅卷人能稳定区分），这是我知道的缺口，不是不知道。"

### 疑点 2：排序数值是随便取的吗？

**事实（`mastery.py` 源码）：**
| 参数 | 值 | 出处 |
|---|---|---|
| λ（遗忘速率） | 0.05 | 艾宾浩斯遗忘曲线的常用近似（e^-0.05t，30 天 ≈ 0.22） |
| 复习答对涨幅 | ×1.5 | 间隔重复系统（SRS）的常见倍率（fail 题 0.3 答对 3 次到 1.0） |
| 双因子权重 | 0.5 / 0.5 | 相关性+重要性对半 |
| status 权重 | fail 1.0 / partial 0.6 / pass 0.2 | "答错的题最该复习"的排序语义 |
| 初始掌握度 | fail 0.3 / partial 0.6 / pass 1.0 | 与 status 权重方向相反（栽得越惨起点越低） |

代码注释和 README「已知边界」都明确写了"**初值待校准（≥50 条真实数据后校准）**"。

**诚实结论：** 机制是标准 SRS（指数衰减 + 三态重置 + 双因子），**常数是"有理论出处的初值"，不是随意取的**，但确实**没校准过**。校准需要真实数据积累——这是坦诚的边界，不是 bug。

**面试讲法：**
> "参数我标了'待校准'，不装已校准——校准需要 ≥50 条真实复习数据，这是数据积累问题不是设计问题。我守住的是：机制的正确性（衰减边界、排序单调性、幂等）由 187 个纯函数测试兜底，这部分是可复现、可验证的；参数口径留给数据，比编一个好看的数诚实。"

### 疑点 3：三源出题具体怎么实现的？

**事实（`run_mock_interview.py`）：** 准确说是**四层来源**（简历/JD/错题本/方法论），实现是"**一次 LLM 调用生成章节化计划**"：

```
plan_interview(resume, jd, weak_items)
  输入（系统侧确定性准备）：
    · resume/JD：data/ 下 .pdf → .md → .txt 优先级读取
    · weak_items：fail+partial 全部 → mastery.rank() 双因子排序 → top 5
  过程：一份 prompt 要求 LLM 输出固定结构 JSON：
    自我介绍 1 题 / 项目深挖 3 题（简历）/ 技术验证 3 题（JD能力项 + 薄弱项）/ 行为面 1 题（STAR）/ 动机面 1 题
    · 薄弱项题必须「原题照抄 + 带 item_id」
    · 方法论（STAR/宝洁八大问）内嵌在 prompt 指令里
  防御（防 LLM 幻觉绑定）：
    · weak 题必须与错题原文【完全一致】才绑定 item 对象，否则降级为 generic
```

**诚实结论：** 是"系统选材 + LLM 组合"的流水线，不是三个独立出题模块；选材排序是确定性的（可测），组合是 LLM 的（不可测，是 eval 缺口所在）。题量固定 9 题/场，章节顺序固定。

**面试讲法：**
> "系统负责选什么——简历、JD 能力项、按遗忘双因子排序的前 5 道薄弱题；LLM 负责怎么问——组合成章节化计划；系统负责防伪——薄弱题必须原文匹配才绑定到错题本条目，防止 LLM 张冠李戴。选材层我可以用测试验证，组合层正是我做 eval 的地方。"

### 疑点 4：系统怎么通过一次次面试反馈进一步优化面试，达到"记住你"？

**事实（写回链路 `_write_back` / `record_result` / `_collect_new_item` / `summarize_behaviors`）：**

每场面试结束 → 三件事写回：
1. **weak 题**：按表现更新掌握度（pass ×1.5 / fail 封顶 0.5 / partial 重置遗忘时钟）+ 合并行为标签 → 下次 `get_weak_questions()` 的 rank 排序自然变化 → 出题选材跟着变。
2. **新题自动采集**：答差的简历/JD/行为/动机题自动进错题本（`source=mock_interview` 可追溯，`answer` = LLM 反馈文本作首个参考答案）。
3. **行为特征**：`summarize_behaviors` 总结「答不到点 / 表达绕弯 / 回避问题」→ 存 `behavior_tags` → `run_remind` 提醒时带上。

「记住你」= **三层**：题目层（哪题栽过，自动积累）→ 状态层（掌握度按遗忘衰减，动态决定提醒优先级和出题选材）→ 人层（行为特征标签，跨题稳定存在）。

**诚实结论：** 目前是"**数据回流**"（结果改状态，状态改选材），**不是"策略自适应"**——出题 prompt 是静态的，不会因为你的历史表现改变追问风格或难度。扩展点 4（动态智能体循环）正是补后者。**面试官追问到这层必须主动承认，否则露馅。**

**面试讲法：**
> "记忆闭环是三层写回：题目、掌握度状态、行为标签。每次面试的结果都回流成下次面试的选材和提醒依据——这是目前实现的'记住你'。我要诚实区分：现在是数据回流层面的动态，出题策略本身还是静态的；跨题自适应是下一个迭代（评估先行）。"

### 疑点 5：模拟面试追问环节怎么实现的？追问有依据吗？

**事实（`interview_one` / `judge_followup` / `get_expected_points`）：**

```
首答 → judge_followup 强制结构化输出：
  {need_followup, followup_question, reason, performance}
       │
       ├─ need_followup=true 且 未满 3 轮 → 追问（围绕漏掉的细节/数字/取舍）
       ├─ 否则 → 本题结束，下一题
硬约束（代码里真实存在）：
  · 轮次上限：首答 + 2 追问 = 3 轮封顶
  · 空回答直接 fail，不调 judge
依据来源：
  · 有参考答案（错题本 item.answer）→ 直接用
  · 无参考答案 → LLM 现场生成 3-5 个期望要点（_EXPECTED_POINTS_PROMPT）
```

**诚实结论：** 追问**有依据**（期望要点 vs 你的回答的差距），但两个洞：
1. **自指循环**：简历/JD/行为/动机题没有独立参考答案，期望要点是**同一个模型**凭题目现编的 → 追问标尺由"出题人"自己定 → 分数衡量的是"答得像不像出题人预期"。
2. **设计与实现 gap**：设计文档承诺的「跨题阻断」硬约束（追问不得引用其他题内容）**代码里没有实现**——只有轮次上限。面试被问到要么说"在 prompt 层面约束"，要么承认后补。

**面试讲法：**
> "追问不是 if-else，是每轮让面试官输出结构化判断（要不要追、追什么、依据是什么），系统只卡轮次上限和安全边界。追问的标尺是期望要点——错题本有参考答案的用真答案，没有的是 LLM 现场生成。这个'现场生成'是我要诚实指出的自指风险，所以设计了 L2 独立金标准（人工补参考答案）来解耦。"

### 疑点 6：面试反馈和出题者是同一个，如何保证可信度？

**事实：** 出题（`plan_interview`）和判卷（`judge_followup`/`judge_single_round`）调**同一个 `chat_json`，同一个模型**。现有缓解手段：
1. **结构化输出**：判卷强制输出 JSON 结构，不自由发挥。
2. **期望要点对照**：先列要点再比对，不是直接拍分数。
3. **用户最终拍板**（仅前端）：判定卡三选，LLM 建议只是预选（CLI 版没有，直接采信 LLM）。
4. **状态机留痕**：每次 status 变更留证据链；判卷写回只动 mastery（连续值），**不改 status（历史事实）**。

**诚实结论：缓解 ≠ 根除。** 同源风险真实存在，这也是你最尖锐的自省点。已定三档修复（2026-08-19 上午设计定稿，待落地）：

| 档 | 内容 | 状态 |
|---|---|---|
| **L1 量规解耦（必做）** | 固定评分量规（正确性/完整性/深度/表达 + 锚点）；阅卷 LLM 只看（题, 答案, 量规）且必须引原文证据，看不到出题 prompt | 待落地 |
| **L2 独立金标准（推荐）** | weak 题用 `item.answer`；简历/JD/行为/动机题人工补参考答案 → 阅卷对照金标准而非合成要点（顺手还"缺答案对照"的债） | 待落地 |
| **L3 判别 eval（置信度唯一证明）** | 每题备 good/mediocre/bad + 自信错答 4 个样本，断言 score 严格递减 + 自信错答不被骗 | 待落地 |

**面试硬话：**
> "出卷/阅卷分离：阅卷人只看固定量规 + 独立参考答案，看不到出题 prompt；用判别 eval 证明阅卷人能稳定区分好/坏答案——分数才可信。这是我现在最明确的改进项。"

## Part 2 · 七个扩展点评估

> 评分维度：**展示价值**（demo/面试杀伤力）、**核心对齐**（是否强化「记忆+主动性」Agent 内核）、**成本**、**风险**。结论给 Now / Next / Later。

### 1. 主动提醒接入微信 —— ⏸ Later（风险高，收益小）

| 维度 | 评估 |
|---|---|
| 展示价值 | 中低——Windows toast 已经够讲故事（"每天 22:00 静默检查，有快忘的才弹"） |
| 核心对齐 | 中——触达率确实提升（微信必看，toast 可能看不到） |
| 成本 | 高——个人微信无官方 API：itchat/wechaty 有**封号风险**；企业微信/公众号要服务器+域名+审核；微信提醒还要处理链接跳转 |
| 风险 | 合规风险高，简历上写"接入微信"反而容易被追问到封号/合规问题 |

**建议：** 不做微信。如果一定要"手机也能收到提醒"，**Server酱 / Bark 一行 HTTP 请求**就能推送到手机，零风险零成本，半天搞定，足够讲"多端触达"。

### 2. 面试结果追问评分 + 导出 —— ✅ Now（低成本高完成度）

- **现状**：复盘报告**已经生成**（`last_review.md`，逐题复盘+共性建议+行为特征）；判卷链路已有（`judge_single_round`）。
- **导出** = 把 markdown 包装成 PDF（或用现有 HTML 报告），纯包装活，~0.5 天。导出后"面试 → 复盘 → 留存"闭环完整，面试时可以现场演示。
- **追问评分** 不单独做——并入 L1 量规解耦（固定量规打分就是"追问评分"的产品形态）。
- **风险**：无。

### 3. 前端状态机流转可视化（章节实时高亮）—— ✅ Next（选做，demo 效果强）

- **现状**：`frontend/app/mock-interview/page.tsx` 已有 phase 状态机（loading/setup/question/judging/verdict/report）、setup 页章节分组预览、答题时显示当前章节名。**缺的是"章节 stepper + 实时高亮"**（自我介绍→项目深挖→技术验证→行为面→动机面，哪章进行中哪章高亮）。
- **成本**：0.5-1 天（纯前端组件，数据已有 `q.section`）。
- **价值**：demo 时考官一眼看到"面试官在哪个环节"，配合复盘报告，Agent 叙事完整。
- **建议**：如果这周要演示，值得做；否则排 eval 后面。

### 4. 动态智能体循环（根据当场表现决定深挖还是换题）—— 🎯 Next 核心（但排 eval 后面）

- **现状（已有一半）**：追问判断已经动态（`judge_followup` 每轮决定追不追）。
- **缺的另一半**：跨题动态——答得好的章节少问、答得差的章节多问/换题、难度自适应、章节时长自适应。目前题量固定 9 题、章节固定。
- **价值**：**最"Agent"的部分**，直接回应"你的系统会不会根据我改变"。
- **成本**：1-2 天（状态机改造 + LLM 结构化判断 + 测试）。
- **前提**：**必须先落地 L3 eval**——否则"改成动态"后没有任何办法证明它变好了，又回到"功能堆砌、无法量化"的怪圈。
- **建议**：这是扩展点里最值得做的，但顺序在 eval 之后。

### 5. 多面试人格 —— ⏸ Later（展示性 > 实用性）

- **价值**：展示性强（"压力面/温柔面/追问狂魔"），但和核心价值「记住你」弱相关。
- **成本**：中（多 prompt + 人格状态 + 出题风格差异）。
- **风险**：容易做成"换皮"——面试官追问"人格除了换 prompt 还有什么区别"时难回答。
- **建议**：如要做，只做**「压力面」单一人格**——演练高压场景对真实面试最有价值，且可讲"压力面 = 固定量规里更严的锚点 + 更深的追问"，不是一个口号。

### 6. 遗忘曲线可视化（每道题掌握度随时间衰减）—— ✅ Now（数据已有，性价比之王）

- **现状**：
  - Dashboard 已有**聚合版**：按距今天数分桶（0-1/1-3/3-7/7-14/14-30/30+）的平均有效掌握度曲线 + 最近复习事件（`app/api/dashboard.py`）。
  - `run_viz.py` 生成单文件 HTML：分层概览 + gap 条形图 + 理论遗忘曲线。
  - `review_log.jsonl` 已记录**每道题**的复习事件（item_id / question / before / after / action / actor / time）——**per-question 时间序列的数据已经在了，只是没画**。
- **缺的**：每道题自己的掌握度轨迹折线图（或热力图：题 × 时间 × 掌握度）。
- **成本**：~0.5 天（读 review_log + ECharts 折线/热力图，`run_viz.py` 已有基础）。
- **价值**：直接打"Excel 换皮"质疑——"别的工具记字，我这个能画出每道题怎么遗忘、怎么被复习救回来的"。

### 7. 短期记忆 + 长期记忆 —— ✅ Next（先叙事后代码）

- **现状**：
  - **长期记忆 = 错题本**（Chroma 持久化，跨会话）——已实现且是核心。
  - **短期记忆 = 面试 session**（单题 transcript 在内存中贯穿追问循环）——部分实现；**跨题上下文未做**（面试官不记得这场面试前面问过什么）。
- **建议**：
  1. **先把叙事讲清楚**：记忆管家（长期：错题本+遗忘状态）vs 面试官（短期：本场会话上下文）——"短期+长期"的分层叙事天然成立，面试就能讲。
  2. **代码最小补**：把"本场已问题目 + 前面章节的表现摘要"注入后续章节的判定/出题 prompt（session 级上下文），半天-1天，跨题连贯性立刻可见。
  3. 注意别做成"为做而做"——跨题记忆的真正价值是"面试官记得你前面栽在哪，后面有针对性地追"，这个能讲出场景再动手。

## Part 3 · 出题质量 eval 方案（补"最 Agent 的部分没被量化"）

> 与 2026-08-19 上午定稿的 L1/L2/L3 设计对齐，这里是落地细节。**关键洞察：出题质量 eval 与评分置信度 eval 是同一个 harness 的两面**——"题好不好" = 阅卷人能否在该题上稳定区分好坏答案。

### 核心思路（判别 eval，不靠主观打分）

与其让 LLM 给自己的题打分（又回到自指），不如**构造已知好坏的标准答案样本，看阅卷人能否区分**：

```
对每道题准备 4 个答案：
  good        —— 覆盖全部要点，条理清晰
  mediocre    —— 覆盖一半，含糊
  bad         —— 明显不会/跑题
  confident   —— 自信地答错（表面流利，全是错的）
断言（写成 pytest 可跑）：
  ① score(good) > score(mediocre) > score(bad)   → discrimination（能区分好坏）
  ② confident 不被判 pass                         → no_fool（不被自信迷惑）
  ③ 该题 bad 能被稳定判 fail / good 能被稳定判 pass → question_pass（题本身可判）
```

### 落地步骤（~1 天）

1. **写量规（L1）**：固定评分维度 正确性 / 完整性 / 深度 / 表达，每题附"锚点"（这道题的必须点）；阅卷 prompt 只收（题, 答案, 量规），必须引用原文证据，**看不到出题 prompt**。
2. **构造判别样本（L3）**：用 `data/resume.md` + `data/jd.md` + 现有错题出 10-15 题，每题手写 4 个答案（good/mediocre/bad/confident）→ 40-60 条样本。**这是人工活，但一次投入永久复用。**
3. **写 `eval/mock_interview_eval.py`**：复用 `judge_single_round`/`judge_followup` 作被测阅卷人；风格对齐现有 `retrieval_eval` + `llm_judge_eval`（JSON 落盘 + 人工校准注释）。
4. **指标**：`discrimination_rate`（顺序断言通过比例）、`no_fool_rate`（自信错答未判 pass 比例）、`question_pass_rate`（单题可判比例）。门槛：discrimination ≥ 0.8、no_fool = 1.0。
5. **不合格题人工复核 → 回修**：哪类题区分度差，说明题本身有问题（太泛/太难/有歧义），回修出题 prompt。

### 为什么这能回答"最 Agent 的部分"

| 质疑 | 这个 eval 的回答 |
|---|---|
| "出题质量没量化" | question_pass_rate：X% 的题能被稳定判好坏 → 题有区分度 |
| "评分同源不可信" | 阅卷人分离（只看量规）+ discrimination/no_fool 证明分可信 |
| "187 测试管不到语义层" | 这是语义层第一个可复现的量化 eval，与 retrieval_eval 同级 |

### 门槛建议

- **L1 + L3 必做**（一天，独立可交付）。
- **L2 推荐**（L3 样本里顺手把参考答案写了；weak 题直接用 `item.answer`，简历/JD/行为/动机题补 10-15 条人工参考答案）。
- 做完之后 README「可验证成果」加一行：*模拟面试出题质量判别 eval：discrimination ≥0.8，no_fool =1.0（N 题 × 4 样本）*——这句比"187 个测试"更能打。

## 附：面试答辩高频追问预案（新增 3 条）

**Q：187 个测试都在测什么？有没有测过 LLM 部分？**
A：187 个全是确定性机制的单元测试（衰减/排序/状态机/幂等/面试循环逻辑，LLM 全 mock）。LLM 部分我有两个小样本 eval（检索 Recall@5=0.704、打标 0.963），出题质量的判别 eval 正在落地——这是我知道的边界。

**Q：λ=0.05 这些数哪来的？**
A：理论出处的初值（艾宾浩斯近似 + SRS 惯例），代码标注"待校准"。机制正确性由测试兜底，参数口径留给 ≥50 条真实数据。我不装已校准。

**Q：面试官出题又判卷，分数怎么信？**
A：三件事：① 阅卷只看固定量规 + 独立参考答案，看不到出题 prompt；② 判别 eval 证明能区分好/坏/自信错答；③ 前端最终判定由用户拍板，LLM 只是建议。当前实现有缓解但未根除，L1/L2/L3 是我排第一的改进项。
