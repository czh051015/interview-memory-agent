## 0. 定位修正一句话

> 旧方案：分析面经市场趋势，输出"市场在考什么"——**你是旁观者**。
> 新方案：记住你的知识状态，输出"你还缺什么"——**你是参与者**。

---

## 1. 核心转变：从情报管道到成长引擎

| 维度 | 旧方案（AgentLoop） | 新方案（秋招 Copilot） |
| --- | --- | --- |
| **系统记忆谁** | 面经市场（外部趋势） | **你的知识状态**（内部掌握度） |
| **核心资产** | 面经趋势数据 | 你的错题本 + 掌握度曲线 |
| **核心循环** | 面经→聚类→简报→读完结束 | 面试→答错→记住→下次提醒→再面再沉淀 |
| **简报输出** | "Agent 框架在涨、RAG 还是稳的" | "你上次 RRF 答错了，8 天没复习，本周优先" |
| **用户角色** | 旁观者（读报告） | 参与者（你的每次面试都在喂系统） |
| **Agent 本质** | 无状态的 LLM 调用管道 | **有状态的 Agent——记住你、随时间进化** |
| **竞争力锚** | 比 9.9 元面经资料快 | **比任何面经资料多一个"关于你的记忆"** |

## 2. 核心 Agent 设计（四个 Agent 共用一个中央记忆库）

### 2.1 Agent 1 — 面经消化 Agent

**一句话职责**：你把面经丢进来，它拆成结构化 Q&A，标注哪些答错了。

**输入**：原始面经文本（手动输入，含公司、岗位、面试轮次）
**核心能力**：语义拆解 + status 打标
**输出示例**：
```jsonc
{
  "company": "腾讯", "role": "AI应用开发", "round": "技术二面",
  "items": [
    {
      "question": "Chroma 和 Milvus 怎么选型",
      "user_answer_summary": "答了轻量场景用 Chroma、大规模用 Milvus，但没说具体性能差异",
      "expected_answer_summary": "需对比延迟/吞吐/扩展性/部署复杂度四个维度",
      "status": "partial",
      "topic": "向量数据库选型"
    },
    {
      "question": "RRF 重排序原理",
      "user_answer_summary": "没答上来",
      "expected_answer_summary": "RRF 通过倒排排名加权融合多路召回结果",
      "status": "fail",
      "topic": "混合检索"
    }
  ]
}
```

**技术手段**：
- 规则层：识别"Q: / A:" 等面经常见分隔格式
- LLM 层：对非结构化段落做 Q&A 抽取 + status 判断（pass / fail / partial）
- `status: "fail"` 和 `"partial"` 的条目自动写入记忆库

### 2.2 Agent 2 — 知识记忆 Agent

**一句话职责**：记住你答错的每一题，跟踪掌握度变化。

**核心依据**：四步记忆理论——结构 → 写入 → 管理 → 读取。

#### ① 结构定义：要记什么

```jsonc
// KnowledgeItem — 每个知识点一条记录
{
  "id": "ki_001",
  "question": "RRF 重排序原理",
  "topic": "混合检索",
  "company": "腾讯",
  "role": "AI应用开发",
  "status": "fail",                    // fail | partial | pass
  "user_answer_summary": "没答上来",
  "expected_answer_summary": "RRF 通过倒排排名加权融合多路召回",
  "mastery_score": 0.85,               // 0.0-1.0，随时间衰减
  "last_reviewed_at": "2026-08-22T14:00:00Z",
  "review_count": 3,
  "created_at": "2026-08-15T10:00:00Z",
  "related_items": ["ki_005", "ki_012"]  // 关联的其他知识点
}
```

#### ② 写入：什么时候记

- 每次面经消化完毕，`status: fail` 或 `partial` 的条目自动写入记忆库
- 写入时 `mastery_score = 1.0`（刚学完、记得最牢）
- `last_reviewed_at = now()`
- 同类题目（同 topic、相似语义）做**合并**：如果已在库中，更新而非新建

#### ③ 管理：怎么维护

**遗忘衰减**（参考艾宾浩斯曲线）：
```
mastery_score(t) = 1.0 × e^(-λ × t)
其中 t = 距 last_reviewed_at 的天数
    λ = 衰减系数（默认 0.05，即约 14 天后降至 0.5）
```

**复习重置**：每次用户复习该知识点后，`mastery_score` 重置为 `min(1.0, 上次分值 × 1.2)`，`last_reviewed_at` 更新。

**清理**：`mastery_score < 0.2` 且 `review_count ≥ 3` 的知识点——意味着反复学反复忘——标记为"顽固错题"而非删除，简报中单独提醒。

#### ④ 读取：怎么召回

不是简单的语义检索，是三维修正排序：
```
recall_score = relevance × 0.5 + importance × 0.3 + (1 - time_decay) × 0.2

relevance:    与当前面经/JD 的语义相似度（Chroma 查询）
importance:   该知识点被标记为 fail 的次数 / 总面试次数
time_decay:   1 - mastery_score（即忘得越多、越要召回）
```

### 2.3 Agent 3 — 成长评估 Agent

**一句话职责**：不只是"Agent 框架在涨"，而是"**你**在 Agent 框架上的掌握度在降"。

**核心能力**：
| 评估维度 | 含义 | 数据来源 |
| --- | --- | --- |
| 薄弱领域识别 | 哪个 topic 的 fail + partial 占比最高 | KnowledgeItem 统计 |
| 遗忘预警 | 哪些知识点的 mastery_score 已低于阈值（如 0.3） | 衰减函数计算 |
| 对比变化 | 相比上周，哪些知识点从 fail 变 pass、哪些退步了 | 历史快照对比 |
| 面试准备度 | 给定一个目标公司+岗位，综合评估你离面过的水平还差多少 | 面经库 + KnowledgeItem |

### 2.4 Agent 4 — 模拟面试 Agent（v2 起）

**一句话职责**：基于你的简历和错题本，扮演面试官追问你的薄弱点。

**核心设计**：
- 从 KnowledgeItem 中取 `status: fail` 且 `mastery_score < 0.5` 的题目优先提问
- 用户回答后自动打分 → 更新 mastering_score
- 追问逻辑：基于上一轮回答追深层问题（如你答了"RRF 是排名融合"，追问"RRF 和加权求和融合的区别"）

## 3. 用户工作流

```
┌─────────────────────┐
│ 每天：刷牛客看面经   │
│ 有面试就记复盘       │
└────────┬────────────┘
         ▼
┌─────────────────────┐
│ Agent 1 面经消化     │  ← 扔进去就拆 Q&A，自动打 pass/fail
│ 知识自动入库         │
└────────┬────────────┘
         ▼
┌─────────────────────┐
│ Agent 2 记忆管理     │  ← 掌握度自动衰减，到期提醒复习
│ 遗忘曲线 + 合并      │
└────────┬────────────┘
         ▼
┌─────────────────────┐
│ 每周五：你打开简报   │
│ 看到你上周答错的题    │
│ RR 复习优先级排序     │
└────────┬────────────┘
         ▼
┌─────────────────────┐
│ 你复习完 → 掌握度    │
│ 刷新 → 下周简报继续  │
└────────┬────────────┘
         │
         │  持续迭代
         ▼
┌─────────────────────┐
│ Agent 3 评估报告     │
│ "RRF 从 fail→pass"   │
│ "Agent 安全还在薄弱" │
└────────┬────────────┘
         ▼
  下周继续 + v2 模拟面试
```

## 4. v1 范围修正（Sprint 调整）

| Sprint | 旧方案 | 新方案 |
| --- | --- | --- |
| S0 地基 | 不变 | 不变，但 schema 预埋 KnowledgeItem 字段 |
| S1 入箱清洗 | CSV + Webhook 整篇入库 | **Cleaner 升级为结构化拆解**：解码面经为 Q&A + status 打标 |
| S2 记忆库 | Chroma 存整篇文本 | **按 KnowledgeItem 存**：字段级存储 + 掌握度衰减函数 |
| S3 信号 | 聚类面经趋势 | ▶ 废弃（旧 Scout 的聚类部分）；改造为"薄弱领域统计" |
| S4 评估 | 评估市场信号可靠性 | **改为掌握度评估**：遗忘预警 + 变化对比 |
| S5 简报 | 市场趋势简报 | **改为个人成长报告**：错题回顾 + 遗忘提醒 + 进步对比 |

**不变的部分**：S0 工程骨架、S2 的 Chroma 基础设施、CI + eval 框架、审批 Streamlit（改为"复习打卡"）

## 6. 为什么这个方案比旧方案更有竞争力

| 问题 | 旧方案 | 新方案 |
| --- | --- | --- |
| 小红书 9.9 元面经能替代吗 | 能替代一部分（他们也有考点总结） | **不能**——他们没有"关于你的记忆" |
| ChatGPT 能替代吗 | 能（丢面经进去让它分析） | **不能**——ChatGPT 记不住你上周答错了什么 |
| 偏离 Agent 开发吗 | 不偏，但深度不够 | **不偏且更深**——记忆系统是 Agent 开发核心命题 |
| 可持续迭代吗 | 可，但方向模糊 | **清晰**——你的每一场面试都是新数据、新燃料 |
| 面试时最好讲什么 | 管道设计 + 评估体系 | **记忆系统设计 + 真实使用故事** |

## 8. 面试叙事线（30 秒电梯陈述）

> 我做的是一个带长期记忆的 Agent 系统——秋招 Copilot。我把每场面试的复盘丢进去，系统自动拆成 Q&A、标出哪些答错了，然后依据艾宾浩斯衰减曲线跟踪我每个知识点的掌握度。每周它给我一份个人成长报告——"你上周 RRF 答错了，8 天没复习，mastery 降到 0.18，本周优先"。它不是分析面经市场的产品，它只关心我。我做这个不是因为好玩——是我明天下周还有面试，我的错题本不能靠脑子记。

**面试官可能的追问 → 你的回答**：

- "这跟丢面经给 ChatGPT 有什么区别？" → "ChatGPT 没有记忆。它不知道我上周在这道题上答错了。我的系统会——而且掌握度是随时间自动衰减的，不是永远记住。"
- "你怎么验证系统记忆是准的？" → "每一次面试就是一次验证。我面完把结果录进去，系统会告诉我哪些它预测我没掌握的东西我真的没答上来。这是真实的 eval 数据，不是构造的测试集。"
- "技术难点在哪？" → "三件事。Cleaner 怎么从非结构化面经文本准确拆出 Q&A 并判断 status。记忆系统怎么平衡遗忘衰减和重要意义之间的关系。成长报告怎么让人看了真的去复习——而不只是'看起来漂亮'的 LLM 输出。"
