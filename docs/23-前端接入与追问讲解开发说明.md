## 1. 后端改动（文件：`app/api/shenlun.py` + `src/mock/{prompts,runtime}.py`）

### 1.1 `src/mock/prompts.py`
新增 `EXPLAIN_PROMPT`：针对单个漏点返回 `rephrase`（换更口语/易懂的说法）、`why`（为什么材料这句能支撑这个点）、`distinguish`（与相邻点的辨析）。**占位符约束：只讲解，不替用户写完整作答段落（守 `no_full_answer` 代写红线）。**

### 1.2 `src/mock/runtime.py`
- 新增 `ExplainResult`：`point_id / point / material_source / rephrase / why / distinguish`
- 新增 `explain_point(material, answer, points, point_id) -> ExplainResult | None`：先取 `material_source`（score 锚定，0 token），再调 `EXPLAIN_PROMPT`；LLM 失败不阻断，`rephrase/why/distinguish` 置空。

### 1.3 `app/api/shenlun.py`
- 新增 `POST /shenlun/practice/explain`（`ExplainRequest`：`gold` 内联或 `question_id` + `point_id` + `answer`），返回 `{point_id, point, material_source, rephrase, why, distinguish}`；`point_id` 不在集 → 404。
- `SubmitRequest` / `GuidanceRequest` / `WrongbookRequest` 均支持 **inline `gold`**（解题库依赖，单题上传主路径）；`_resolve()` 优先用 `gold`，否则按 `question_id` 读题库。
- 四个端点完整清单：`practice/submit`（L1 评分+推1个最该补）、`practice/guidance`（按需 L2/L3/L4）、`practice/explain`（有界追问）、`wrongbook`（按漏点一条入库）。

## 2. 前端改动

### 2.1 `lib/types.ts`（新增/对齐）
- `InlineGold`：`{points, material, question, qtype}` —— 单题上传内联题面
- `PracticeHit` / `PracticeMiss` / `PracticeLeading` / `PracticeSubmit` —— L1 评分结果（命中带 `matched_text`，漏点带 `material_source`）
- `GuidanceResult`：`{point_id, point, material_source, demo, cause_type, cause, fix}`（L2/L3/L4）
- `ExplainResult`：`{point_id, point, material_source, rephrase, why, distinguish}`（有界追问）
- `WrongbookResult`：`{stored, item_id, point}`

### 2.2 `lib/api.ts`
- **删除**：旧 `startPractice` / `submitPractice` / `completePractice`（旧范式：题库出题 + 多轮逼问循环）
- **新增**（均走 `post`，自带 `gold`，前端无状态）：
  - `scorePractice(gold, answer) -> PracticeSubmit`
  - `getGuidance(gold, answer, point_id) -> GuidanceResult`
  - `getExplain(gold, answer, point_id) -> ExplainResult`
  - `addWrongbook(gold, answer, point_id, demo, cause_type, cause) -> WrongbookResult`

### 2.3 `components/workbench/PracticePanel.tsx`（整体重写）
- **输入区**：题干 / 给定材料 / 标准答案（采分点 JSON）/ 作答 四个框 + 「载入示例题」按钮（内置 henan_2025 数据，点一下即可试跑）
- **评分（L1 全透明）**：提交 → `scorePractice` → 渲染命中（绿 chip + `matched_text` 片段 tooltip）/ 漏点（红 chip + 每点挂「材料第X段：『…』」）；历史轮次可折叠「评分过程」区体现透明
- **推 1 个最该补**：`leading` 自动展开其 L2/L3/L4（对齐 CLI 体验）
- **点其他漏点**：`getGuidance` → 展开该点 L2 示范 / L3 材料原话 / L4 错因+改法
- **每漏点「追问讲解」按钮**：`getExplain` → 展开换说法/为什么/辨析（底部标「仅讲解，不替你写完整答案」）
- **每漏点「＋错题本」**：`addWrongbook`（没展开过示证会自动补一次 `getGuidance`，保证 demo/cause 有值）
- **「再改一版」重评分**：用户贴改后作答 → `scorePractice` → 追加轮次，显示「🎉 本轮新命中」delta；重评分复用 `score_answer`（**0 token**），只对新漏点出 LLM 示证
- **删除**：旧多轮逼问循环（`MAX_ROUNDS` / `canSubmit` / `showFinish` / 读 `r.guidance` 旧字段，API 已无此字段）

## 4. 运行方式

**后端**（FastAPI，8000）：
```bash
cd offerloop
python -m uvicorn app.main:app --reload --port 8000
```
> 前端 `next.config.ts` 的 `rewrites` 已把 `/api/*` 代理到 `http://localhost:8000`。

**前端**（Next.js，3000）：
```bash
cd offerloop/frontend
npm run dev          # 开发：http://localhost:3000
# 或 npm run build && npm run start   # 生产
```

**快速试跑**：打开 workbench 页面 → 点「载入示例题」→ 在作答框粘贴一段 imperfect 作答（如 CLI 里那条只写设施互通/人才共育的）→ 点「评分」→ 看 L1 + 推1个示证 → 点其他漏点看 L2/L3/L4 → 点「追问讲解」→ 「再改一版」补上漏点重评看 delta → 「＋错题本」。

## 6. 注意事项 / 陷阱

1. **内联 vs 题库**：前端只走 inline `gold`（单题上传）。题库 `question_id` 路径在后端保留但前端未接；以后做「示例题」入口只需加按钮填 `gold`，不影响现状。
2. **代写红线**：L2 示范与「追问讲解」都只给骨架/方向，`no_full_answer` 不可破。若后续想让讲解更接近满分答，需重新评估该红线。
3. **错题本 inline 模式**：`wrongbook` 端点 inline 模式合成 `ctx={"id":"inline"}`，落库走 `knowledge_store.store_items`（与面试域同库）。`material_source` 由服务端用 score 重算（锚定可溯源），LLM 产物（demo/cause）前端回传免重复调。
4. **重评分 0 token**：`score_answer` 是纯字符串匹配，反复「再改一版」不烧 LLM；只有本轮新出现的漏点才需要 `guidance`/`explain` 调 LLM。
5. **类型命名**：`PracticeStart` / `PracticeRound` / `PracticeComplete` 已从 `api.ts` import 移除（旧范式），`types.ts` 中保留定义不影响。
