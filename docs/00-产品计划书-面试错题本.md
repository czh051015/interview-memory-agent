# 面试错题本 · 产品计划书

> **当前唯一权威版本**（v2.0 · 2026-08-13）。
> 本文取代旧的 `product-plan.md`——那是"成长引擎"定位的早期版本，仅作历史参考，不再维护。
> 本文由产品顾问、产品管理、AI 工程师三个视角收敛后重写。

## 一句话定位

一个「记得你」的面试错题本——间隔重复机制 + 自动采集。

## 为什么是这个定位

- 核心资产是**你的错题本**，不是"面经市场分析"。错题本记得你上周 RRF 答错了、8 天没复习——这是 9.9 元面经资料、ChatGPT、百词斩都做不到的。
- 面经库 / JD 是**补给**，不是核心。它们的职责是"你没面够时，帮你填充错题本"，而不是独立成一个"市场分析"功能。
- 考点榜、JD 词频统计是**红海**，砍掉——它把你拽回"爬虫项目"的观感，且毫无差异化。

## 三阶段路线

| 阶段 | 目标 | 做什么 | 不做什么（Non-goals） |
| --- | --- | --- | --- |
| ① 记忆机制（现在） | 让错题本「会记」 | `mastery_score` + `decay` 衰减 + 复习提醒，只对 fail/partial 生效 | ❌ 不调参（λ/权重 ≥50 条后再 eval 校准） |
| ② 面经库（补给） | 让面经「喂」错题本 | 面经题以 `unknown` 入库 + 手动标 `fail` 冷启动 | ❌ 不做考点榜、不做 JD 词频统计 |
| ③ 模拟面试（后置） | 让错题本「被用」 | 读错题本 + 记忆，追问你的薄弱点 | ❌ 不做完整对话系统，先做「出题」 |

## 当前第一步：三件套（最小技术闭环）

1. `KnowledgeItem` 加 `mastery_score` 字段（默认 1.0）
2. `decay(score, days)` 衰减函数，只对 `status ∈ {fail, partial}` 生效
3. `annotate` 动作：把面经 `unknown` 手动标成 `fail`（复用 v1 的 `annotate.py`）

跑通这三件套，系统就从「能存能查」升级成「会记住你、会提醒你」。

## 验收标准（每阶段一个）

> 近的阶段验收细、可量化；远的阶段验收给方向，做的时候再细化。

### 阶段① 记忆机制（当前，可量化）

| 验收项 | 标准 |
| --- | --- |
| `decay` 正确性 | 单测：days=0 返回原值、长期衰减趋近 0、score 截断到 [0,1] |
| `review` 重置 | 单测：复习后 score = min(1.0, score × 1.2) |
| 复习提醒排序 | smoke：21 条错题里，久未复习的 fail 题排最前，人工确认 |
| `annotate` 标注 | unknown → fail 后，该题进入衰减计算 |

### 阶段② 面经库降级（冷启动）

| 验收项 | 标准 |
| --- | --- |
| source 隔离 | 面经题以 unknown 入库，检索按 source 过滤，不混入自己的错题 |
| 手动标注闭环 | unknown → fail 后进错题本，开始参与衰减 |
| Non-goal 守得住 | 系统里没有「考点榜」功能（确认没做宽） |

### 阶段③ 模拟面试（后置，方向性）

| 验收项 | 标准（方向） |
| --- | --- |
| 出题针对性 | 出的题 ≥70% 来自用户的高频错误 topic |
| 反馈闭环 | 答错的题能回流错题本，标回 fail |

> **参数调优（λ、三元权重）不属于任何阶段的验收**，统一延后到错题 ≥50 条后用 eval 脚本校准。

## 风险与待定

| 风险 | 缓解 |
| --- | --- |
| 应届生面试少，错题数据不足 | 面经库冷启动（阶段②）填补 |
| λ 衰减系数是初值，未校准 | 明确标注，≥50 条后校准 |
| 阶段②③ 依赖阶段①的 KnowledgeItem 数据 | 先跑通①，数据自会积累 |
