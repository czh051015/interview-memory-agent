## 0. 背景与范式转变

**现状问题**：当前逼近引导跑的是 `src/mock/prompts.py` 的 `_APPROACH_PROMPT`（苏格拉底式逼问："`[S]句附近——想一想这对应哪个漏掉的点？该点你写到了吗？"`）。这是用户上轮明确否定的"追问"形态。效果不好的根因 = 提示词死板、一股脑把全部漏点丢给 LLM 让它生成方向提问。

**范式转变**：从"考你"（题库出题 + 逼问循环）→"帮你"（上传 + 评分 + 示证）。示证 = 标红漏点 + 材料原话 + 示范表述 + 错因诊断，让用户"被看见"，不是"被追问"。

**本次范围**：先后端 + CLI，eval 验证示证逻辑，前端暂搁置（见 §7）。

> 注：`docs/21` 写的"3 级精度引擎 + L1–L4 报告体系 + 录入时 LLM 拆解采分点并永久缓存"与代码严重不符，且核心假设错误——benchmark `gold.reference_points` 本就是结构化采分点，**上传解析 0 token，无需 LLM 拆解**。本方案取代 21，按其落地。

## 1. 设计决策定稿（grill 收口，已拍板）

| 编号 | 决策 | 内容 |
|---|---|---|
| Q5(c) | 评分 hook 形态 | 命中/漏点列表 + **每个漏点挂一句材料原话**轻量溯源（建立"可核对"信任，省 token） |
| Q6(a) | 存储模型 | 上传解析结构化标准答案（0 token）/ session 内缓存 / **结束即丢、不建永久题库**；加入错题本是唯一持久化路径，须当场 snapshot |
| Q7(b) | 引导触发 | 默认**只推 1 个最该补的漏点 + 示证**，其余折叠（示证式主动，非逼问） |
| Q9(a) | 首 session 兜底 | 无错题本历史时，按 `reference_points.score` 挑权重最高的漏点推 |
| Q8 | 度量 | **不埋点**，用户主观判"信任 + 愿接受" |
| Q11(a) | 前端现状 | `offerloop/` 已有 Next.js 前端且接申论评分，但走坏范式（题库出题+逼问），本次不改 |

**四层级定义**（L1 默认给，L2–L4 用户点开才展开，绝不做系统自动"再写一遍试试"）：
- **L1 标红定位**：命中句绿 / 漏点红高亮 + 每漏点挂材料原话。判卷即输出，字符串匹配 + 材料锚定，无需 LLM。
- **L2 同义示范**：对每个未命中点，给 1–2 个"这样写就得分"的示范表述。
- **L3 原文溯源**：该采分点在材料中的原文依据（材料锚定，不靠预标注行号）。
- **L4 深度解析**：错因归类（完全没提 / 写偏 / 太模糊）+ 具体改法。

## 2. 新主流程（后端视角，前端暂搁置）

```
用户：粘贴 题干 + 材料 + 标准答案(解析) + 作答
  → score_answer(): 判定 hit/miss，补 matched_text + material_source
  → 返回 L1：命中/漏点列表（每漏点挂材料原话）
  → 排序取"1 个最该补"推送（§4）
  → 用户点开某漏点 → guidance(point_id): 按需生成 L2(DEMO) + L4(CAUSE)；L3 用 score 的材料锚定
  → 用户可选"加入错题本" → snapshot(point + 材料原话 + 示范) 落库
```

## 3. 后端改动切片（Claude Code 实现清单）

### 3.1 `src/cleaner/schema.py` — ReferencePoint 加 `material_source`
- 现有字段（约 line 85）：`id, point, keywords, score, point_type, approved, source, history, created_at`
- **新增**：`material_source: str | None = None` — 材料锚定结果，如 `"材料3第2段：'建立常态化的考核评估机制…'"`
- `ScoreResult`（在 `score.py` 内定义）**新增**：`matched_text: str | None = None` — 命中关键词在用户作答中的片段（每次评卷动态算，不放 ReferencePoint）

### 3.2 `src/shenlun/score.py` — 补 `matched_text` + `material_source`
- 函数：`score_answer(answer: str, points: list[ReferencePoint]) -> ScoreResult`
- 现状：任一 keyword 出现即 hit，只出 `hit_points / miss_points + hit_ratio`
- 改：
  - **命中时**：字符串匹配记录该 keyword 在 `answer` 中的片段 → `matched_text`（**0 token，纯字符串操作**）
  - **material_source**：把 `reference_point.keywords` 回 `materials` 句子做重叠度 / 轻量向量检索，取最相关一句 → `"材料X段：'…'"`（**材料锚定，不依赖预标注行号**）
  - 输出：每个 hit / miss point 携带 `matched_text` / `material_source`
- 不动判定核心逻辑（纯关键词命中已验证 discrimination），只加字段。

### 3.3 `src/mock/prompts.py` — 换 prompt
- **删除/替换** `_APPROACH_PROMPT`（苏格拉底式，line 17–46）
- **新增 `DEMO_PROMPT`**（L2）：输入 = `{漏点, 材料原话}` → 输出 1–2 句"这样写就得分"的示范表述
  - 红线：只给表述骨架/关键词，不替用户写完整答案（对应 eval `no_spoiler`）
- **新增 `CAUSE_PROMPT`**（L4）：输入 = `{漏点, 用户答案, 材料原话}` → 输出 错因归类（完全没提 / 写偏 / 太模糊）+ 具体改法
- **L3 溯源不靠 LLM**，直接用 `score.py` 的 `material_source` 材料锚定结果

### 3.4 `src/mock/runtime.py` — `_approach_guidance` 改按需
- 现状：`practice_submit` 里 `if not passed and req.round < MAX_ROUNDS - 1: _approach_guidance` 自动循环
- 改：
  - `_approach_guidance(point_id)` 只生成**单个点**的 L2(DEMO) + L4(CAUSE)
  - **删除自动循环 / decide_next**；改为用户点开才调一次
  - 新增 `guidance(point_id)` 入口，供 CLI（§5）与未来前端按需调用

### 3.5 `app/api/shenlun.py` — `practice_submit` 删自动逼问
- **删除** `if not passed and req.round < MAX_ROUNDS - 1:` 整段自动逼问触发
- 评分后返回 L1 数据 + 推 1 个漏点（按 §4 排序）
- 前端搁置，此路由本次 UI 不改，但后端函数需保留给 CLI 复用

### 3.6 错题本持久化（保留已有真路径）
- 真落库路径：`frontend/app/record/page.tsx` → `app/api/record.py` → `knowledge_store.store_items()`
- ⚠️ `shenlun_record()` 是 demo，**注释写明"只返回拆解预览不落库"**，不可用
- 新范式"加入错题本"接 `/api/record`，**按「每个漏点一条」存入**（不是整题一条）：
  - 复用 `KnowledgeItem`（`src/cleaner/schema.py`，面试域实体）做载体，映射申论字段：
    `question`=题干、`answer`=用户作答片段（matched_text/空答）、`question_type`=题型、`topic`=漏点名(point)、`feedback`=错因(L4)+示范表述(L2)、`status`=fail、`date`=当天
  - **申论扩展字段（建议加进 KnowledgeItem，reflow/提醒要用）**：`point_id`（漏点 id）、`material_source`（材料原话锚点）、`demo_text`（示范表述）、`reflow_tier`（红/黄/绿，初始红）
  - **必存**：`point`+`point_id` + `question_type` + `material_source` + `demo_text` + `cause`(错因) + `user_answer_snippet` + `question_id` + `date` + `status=fail`
  - 目的：喂给 reflow（红黄绿档）与 topK 备考提醒（见 §7），实现"哪类题型/采分点反复漏 + 不遗忘"

## 4. "推 1 个最该补"排序逻辑（Q7b / Q9a）

1. **有错题本历史** → 查 `src/shenlun/reflow.py` 红档（反复漏的点），红档优先（`reflow.py` 已有红黄绿档）
2. **无历史（首 session）** → 取 `miss_points` 中 `score` 最大者（benchmark `reference_points` 自带 `score`，天然兜底）

> 两条分支保证"推 1 个"在任何阶段都有解，不会空转。

## 5. CLI 输入口（Claude Code 建）

- **文件**：`offerloop/src/shenlun/cli.py`（或 `offerloop/cli.py`）
- **输入**：`--question <题干>` / `--answer <作答>` / `--gold <标准答案 json 或解析文本>`
- **行为**：
  1. 解析 gold → `reference_points`（结构化直接解析；散文式才 LLM 兜底，极少）
  2. 调 `score_answer` → 打印 **L1**（命中/漏点列表，每漏点挂 `material_source` 原话）
  3. 按 §4 推 **1 个最该补** + 其示证
  4. 用户命令（如 `show <point_id>`）展开 **L2/L3/L4** → 调 `guidance(point_id)`
- **关键约束**：CLI 调用的后端函数 = eval 复用的**同一函数**，不另写两套逻辑。

## 6. eval 接线（重要：现有 `guidance_eval` 测旧范式，不能复用测示证）

- **`score_eval.py` 保留有效**：测 `score.py` 的 hit/miss 区分力（discrimination + no_fool），不调 LLM、秒级。新设计只给 score 加 `matched_text`/`material_source`，判定核心不动，此 eval 继续适用。
- **`guidance_eval.py` 不能复用测示证**：它测的是旧 `_APPROACH_PROMPT`（苏格拉底逼问），红线（no_position / no_overcopy / no_keyword_spoiler / no_spoiler / evidence_spoiler）的设计意图是"引导但不泄露"，与示证"直接给关键词/示范表述/材料原话"**哲学相反**。拿它跑新后端会系统性红失败（L2 含关键词踩 no_keyword_spoiler、L3 点名材料原话踩 evidence_spoiler）——这不是新设计错，是 eval 测旧范式。
- **需新写一套「示证 eval」**，红线重新定义：
  - 保留 `no_fabrication`：示证点必须真在漏点集 + 材料原话真出自材料（material_source 锚定可溯源，不能编）
  - 把"不泄露"改为"**给得对、给得准**"：**允许**示范含关键词、允许给材料原话、允许给模型表述骨架；**禁止**替用户写完整作答段落（新红线 = `no_full_answer`，非 no_keyword_spoiler）
  - 加「示证命中材料」校验：L3 材料锚定必须真有出处
- **`decompose_eval.py` 保留（前版误判"废弃"，已更正）**：它测 `src.cleaner.decompose.decompose_points`（LLM 拆标准答案→ReferencePoint[]）质量（point_recall≥0.80 / fabrication≤0.10 / structural≥0.94 / 脏标答鲁棒性）。新流程 Q6 主路径虽 0 token，但**散文式标准答案仍需 `decompose_points` 兜底**（§5），且**错题本按漏点拆条存入也可能复用它**；该 eval 仍有对象，继续有效。
- 用户不埋点（Q8）。示证 eval 写好后，改完手动试前跑一次。

## 7. 前端现状与范围（2026-08-31 更新）

- **范式定调（用户拍板）**：单题 + 全透明过程。**不建题库**（题库不当核心流程）；题库数据 + API `question_id` 路径**保留休眠**，以后想接"示例题"随时能加，不删。
- **前端示例页已出**：`shenlun-frontend-example.html`（仓库根，standalone 原型，移动优先）。四输入框预填 henan_2025 样例 → 点「评分」渲染 L1 透明结果（命中绿/漏点红 + 每点挂材料原话）+ 推 1 个最该补自动展开 L2/L3/L4 + 其余点开 + 每漏点「＋错题本」。顶部注释写明如何把内嵌数据换成真实 `/api/shenlun/practice/submit|guidance|wrongbook` 调用。该页= `PracticePanel.tsx` 重写的活规格。
- **真实 `PracticePanel.tsx` 改写步骤（按示例页对齐）**：
  1. `app/api/shenlun.py` 的 `SubmitRequest/GuidanceRequest/WrongbookRequest` 各加一组可选 inline 字段（`gold_points/material/question/qtype`）；有则走 `from_benchmark()` 解析（0 token），`question_id` 留作休眠次路径。

## 8. 验收（用户侧）

1. 跑 CLI：输入例题（题干/答案/标准答案）→ 看 L1 列表 + 推 1 个 + L2/L3/L4 展开是否正常
2. 跑 `score_eval.py`（判定区分力，继续有效）+ 新写的「示证 eval」（§6 红线：no_fabrication + no_full_answer + 示证命中材料）。**注意：旧 `guidance_eval.py` 不能复用测示证**（测旧范式，会系统性红失败）
3. 主观判断"解析值得信任 + 愿接受引导" → 通过后启动前端改造（见 §7）
