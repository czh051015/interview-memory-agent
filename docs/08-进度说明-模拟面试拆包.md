## 4. 关键设计：活引用（本次修测试失败的根因与解法）

**测试的 patch 目标全部是壳模块命名空间**（`monkeypatch.setattr(mi, "DATA_DIR", ...)`、
`@patch.object(mi, "chat_json" / "judge_followup" / "decide_next" / ...)`）。
子模块内部互调若用模块级绑定（`from src.config import DATA_DIR`、`from src.llm import chat_json`、
`from .judge import judge_followup`），patch 壳属性**穿透不进来**——这是 30 项失败的总根因。

**统一解法：子模块一律 `import scripts.run_mock_interview as _mi`，调用时经 `_mi.xxx` 运行时动态查壳属性。**
- 覆盖点：`chat_json`（judge/runtime/plan/report）、`get_expected_points`/`judge_followup`
  （runtime.interview_one）、`generate_dynamic_question`/`decide_next`/`interview_one`
  （runtime.run_dynamic_session）、`_progress_file`（runtime 三个落盘函数）、
  `DATA_DIR`/`space_dir`（plan._read_doc）。
- 循环 import 安全：所有入口（offerloop.py / app/api/mock.py / tests / cli）都先 import 壳，
  `import x as y` 只绑定模块对象不访问属性，部分初始化的壳可安全引用。
- 壳必须 re-export `DATA_DIR`（`from src.config import DATA_DIR`）与 `chat_json`
  （`from src.llm import chat_json`）——真实运行场景子模块经 `_mi.xxx` 取到的就是它们。

**record_result 签名**：writeback 的 `_record_result` 是 4 参（带 judge）；测试用 3 参旧签名。
`record_result` 改为 3 参兼容封装（judge 传 `{}`，不发 feedback），`_build_writeback_items`
内部仍直接调 4 参版。
