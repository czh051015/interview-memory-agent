# 模拟面试 · 评分与评测说明

> 面试前复习用。覆盖：10 个 prompt 契约 / rubric 模式三层构成（正交）/ 五个度量及设计依据 / plain vs legacy 命名映射 / 消融计划 / 已知局限。
> 行号随重构可能变动，以「函数名（文件）」为准。

---

## 0. 全局链路一句话

cli 收集资料（简历/JD/错题本/记忆管家/画像）→ plan 出题（5 章种子题）→ decide_next 决定题间走向 + generate_dynamic_question 现场出题 → judge_followup 控制单题追问 + judge_single_round 单轮判定 → behavior/review 复盘 → apply_verdict 写回错题本（长期记忆）。

---

## 1. 十个 Prompt 契约（触发时机 + 返回字段 + 消费位置）

按面试生命周期 5 类 job 拆；判卷类每个有 plain / rubric 两版（rubric 默认生效），故 5 类 → 10 个。

### 出题阶段（决定考什么）

| 提示词 | 触发函数 | 返回 JSON | 用途 |
|---|---|---|---|
| `_PLAN_PROMPT` (prompts.py:7-23) | `plan_interview()` | `{sections:[{name, questions:[{question, source, item_id, topic}]}]}` | LLM 读三材料生成 5 章种子题池 |
| `_DYNAMIC_QUESTION_PROMPT` (prompts.py:40-46) | `generate_dynamic_question()` | `{question, source, topic}` | 种子池空或 deep_dive 时现场出一道新题 |
| `_DECIDE_NEXT_PROMPT` (prompts.py:26-38) | `decide_next()` | `{action: deep_dive/switch/next_section/end, guidance, reason}` | 每答完一题决定下一题走向 |

### 判卷 / 追问阶段（决定答得怎样、追不追）

| 提示词 | 触发函数 | 返回 JSON | 用途 |
|---|---|---|---|
| `_EXPECTED_POINTS_PROMPT` (prompts.py:49-52) | `get_expected_points()` | `{points:[...]}` | 仅无参考答案时生成标准要点，作后续对照 |
| `_FOLLOWUP_PROMPT` (prompts.py:55-62) | `judge_followup(use_rubric=False)` | `{need_followup, followup_question, reason, performance}` | 单题追不追问（plain 版，fallback） |
| `_RUBRIC_FOLLOWUP_PROMPT` (prompts.py:65-77) | `judge_followup(use_rubric=True)` ←默认 | 同上结构 | 量规版：四维对照 + 引原文证据 |
| `_SINGLE_JUDGE_PROMPT` (prompts.py:80-90) | `judge_single_round(use_rubric=False)` | `{points, misses, suggested, reason}` | Web 单轮判定（plain 版，fallback） |
| `_RUBRIC_SINGLE_PROMPT` (prompts.py:93-105) | `judge_single_round(use_rubric=True)` ←默认 | 同上结构 | 量规版：四维对照 + misses 引原文 |

### 复盘阶段

| 提示词 | 触发函数 | 返回 JSON | 用途 |
|---|---|---|---|
| `_BEHAVIOR_PROMPT` (prompts.py:108-112) | `summarize_behaviors()` | `{tags:[...]}` | 行为特征标签 → 写回错题本（长期记忆） |
| `_REVIEW_PROMPT` (prompts.py:115-122) | `generate_review_report()` | `{overall, items:[{question, performance, problem, suggestion}], common}` | 逐题复盘报告 → 打印 + 落盘 last_review.md（短期） |

**关键事实**：plain 版是 fallback，rubric 版（`use_rubric=True`）才是默认生效。`judge_followup`/`judge_single_round` 的 `use_rubric` 默认都是 True（judge.py）。

## 2. Rubric 模式三层构成（正交）

rubric 带来的提升 = 三层叠加，不全是提示词工程：

| 层 | 是什么 | 代码落点 | 性质 |
|---|---|---|---|
| **提示词工程** | 四维量规 + 强制引原文 + 结构化 JSON | `use_rubric=True` 选 `_RUBRIC_*` prompt（judge.py:46/93） | 控制流零改动，只换 prompt 字符串 |
| **数据注入** | 把 `expected_points`（金标准参考答案）作为对照塞进 prompt | `get_expected_points()`（judge.py:21-22），有参考答案直用，无则 LLM 现编 | 上下文工程 / 数据管线 |
| **调用策略** | `cross_on_partial` 第二判官复核 | judge.py:38/83 参数，runtime.py:99 / app/api/mock.py:200,214 传 True | 系统工程（多次采样 + 复核） |

**正交含义**：三个开关互相独立、改一个不影响另外两个、可自由组合。这就是 "正交"（数学垂直 → 软件里互不耦合可组合）。所以"判卷质量提升 = 提示词工程 + 数据注入 + 调用策略三者叠加，不靠换模型"。

**专业术语**：数据注入 = Reference-based / Grounded evaluation（基于参考的评判）；rubric 本意即"评分量规"。金标准来自题库参考答案字段，缺则 LLM 兜底，但保持量规结构。

## 3. 五个度量及其设计依据

三态映射 `pass=2 / partial=1 / fail=0`（eval.py:42）。每题 4 类答案：good / mediocre / bad / confident（自信但错误）。

| 度量 | 判定 (eval.py:93-97) | 设计依据 | 门槛 |
|---|---|---|---|
| **discrimination_rate** | `good > bad` | 教育测量 IRT「题目区分度」+ ML 判别排序能力底线 | ≥ 0.8 |
| **no_fool_rate** | `confident != pass` | LLM-as-Judge 偏差研究（verbosity/confidence bias）的对抗样本 + 面试安全-critical（FP 危害 > FN） | == 1.0 |
| **order_ok_rate** | `good ≥ mediocre ≥ bad` | IRT 单调性假设（弱序），ordinal scale 有效性 | — |
| **strict_order_rate** | `good > mediocre > bad` | IRT 单调性（强序），等级评分区分度 | — |
| **question_pass_rate** | `good==pass 且 bad==fail` | 题项功能正常检验，分离「阅卷器缺陷 vs 题项缺陷」 | — |

**整体设计哲学**：
- **失败模式覆盖**：覆盖多个独立失败模式，避免对单一指标过拟合（呼应 HELM / OpenCompass 多维度哲学）。
- **fail-closed 校准**：good/confident 必须人工 approved 才跑（eval.py:66-74），杜绝「LLM 标注 LLM 判」循环论证。
- **确定性门槛 + 可串 CI**：门槛写死成 PASS/FAIL（eval.py:163-164）。
- **跨模型验证**：`--cross-model` 用 reasoner 复跑（eval.py:143-145），排除单模型自洽偏见。

**真实基线**（rubric 模式，20260827_224803 轮）：discrimination=1.0、no_fool=1.0、order_ok=1.0、strict_order=0.64（7/11，4 题把 mediocre 判成 fail → 对中等档偏严，是安全偏置）、question_pass=0.91（10/11）。注：strict/qpass 随 LLM 判定有 ±1 题级别轮间波动（与 baseline 快照 0.636/0.909 持平），单轮数字不作精度解读。

## 4. plain vs legacy 命名映射

| 地方 | 非量规版叫法 | 视角 |
|---|---|---|
| prompts.py / judge.py | **plain** | prompt 模板（轻量版 vs 量规版） |
| eval/mock_interview_eval.py | **legacy** (label, eval.py:162) | 产品阶段（修复前现状） |

**为什么两个名字**：旧版 `use_rubric` 一个开关同时控两件事（金标准注入 + prompt 选型）。10 计划已把两者解耦为两个正交旋钮（`use_rubric`=prompt 选型、`inject_reference`=金标准注入，eval.py:67-82），四模式消融见 §5。其中「plain + 不注入」恰好 = 产品修复前整体现状，故 eval 贴 "legacy" 标签而非 "plain"。plain 只描述 prompt 那一半。

## 5. 消融（已完成，10 计划落地）

`evaluate`/`run_judge` 已把 `use_rubric`（prompt 选型）与 `inject_reference`（金标准注入）解耦为两个正交旋钮（eval.py:67-82），`--compare` 跑 A/B/C/D 四组合（176 次 LLM 调用）。归因口径（固定另一旋钮）：**D−C = 注入贡献、D−B = 量规 prompt 贡献、D−A = 整体增益**。

**本轮结果**（20260827_224803，11 题校准样本）：

| 模式 | prompt | 注入金标准 | disc | strict | no_fool | qpass |
|---|---|---|---|---|---|---|
| A legacy | plain | 否 | 100% | 73% | 100% | 91% |
| B plain_inject | plain | 是 | 100% | 82% | 100% | 100% |
| C rubric_no_ref | rubric | 否 | 100% | 73% | 100% | 91% |
| D rubric | rubric | 是 | 100% | 64% | 100% | 91% |

**归因结论**：
- **主指标天花板**：discrimination / no_fool 四模式全部 100%，注入与量规的边际贡献（D−C、D−B）均 +0%——本样本无法分离两旋钮对主指标的增益，属**天花板效应**，不是「注入没用」的证据。
- **次要指标噪音**：strict_order / question_pass 四模式差 ≤ 2 题（9–18pp），且与历史轮相比 strict 有 ±1 题级别随机波动（上轮 0.727 → 本轮 0.64），不构成归因依据。
- **诚实口径**：当前样本只能证明「判卷器在四种配置下均稳定区分（阈值全过）」；要量化「提升来自哪」，需更难的样本（把区分度压离 100% 天花板）才有区分力。

**成本与结构**：+88 次 LLM 调用（一次性），仅动 `eval/mock_interview_eval.py`，不动 runtime / judge / 线上逻辑。

## 6. 已知局限与诚实边界（面试主动讲）

1. ~~A vs D 是修复前后对比，非消融~~ 已完成四模式消融（10 计划）：量规 prompt 与金标准注入的贡献可分离（D-C / D-A 归因见 §5）。
2. eval 默认不开 `cross`（eval.py:77 默认 False），测的是「阅卷人本身」区分力；线上 runtime/app 传 `cross_on_partial=True`（有复核），故 eval 分数比线上略宽松。
3. `strict_order` 偏严（0.727）是「宁可低估不高估」的安全偏置，非 bug。
4. 框架自定义（docstring 标「grill 定稿」），原则有依据（§3）但非某标准库规定；`question_pass` 偏自定义诊断项。
5. 追问循环（interview_one）目前**无评测基准**，只有判卷人有判别基准——追问价值属设计论证 + 可补纠错率基准（见下）。

## 7. 面试讲点速记（口语稿骨架）

- 「模拟面试把简历/JD/错题本喂给 LLM 生成 5 章种子题；运行时靠两层 LLM 决策实现动态——单题层 judge_followup 按回答现场追问（内容动态），场次层 decide_next 按表现决定深挖加题或跳章（题量动态），题数 5~12 浮动但受硬上限约束，最终写回错题本闭环。」
- 「判卷质量 = 提示词工程（四维量规+引原文）+ 数据注入（金标准对照）+ 调用策略（第二判官复核）三者正交叠加，不靠换模型。」
- 「评估框架扎根教育测量 IRT（区分度/单调性）和 LLM-as-Judge 偏差研究（抗自信欺骗），多失败模式覆盖 + fail-closed 校准 + 跨模型验证，门槛写死可串 CI。」
- 「诚实点：已做四模式消融（量规 prompt / 金标准注入贡献可分离），追问循环尚无量化基准，strict_order 偏严是安全偏置——这些我都知道，并有补复盘评测的计划。」

## 8. 一句话总结（面试 / 简历用，按「用户痛点 → 解决思路 → 量化（从多少到多少）」格式）

针对「求职者做模拟面试时，追问抓不住自己刚答岔的真实薄弱点、且拿到的判分不知道准不准、值不值得信」的痛点，采取「① 打通决策→出题的 guidance 管道，让 deep_dive 深挖追问随上一轮回答动态生成（不再硬编码"深挖上一题主题"）；② 把判卷拆成"量规 prompt"与"标准答案注入"两个正交维度做四模式消融，验证判分可靠性」的思路，量化结果是 **抗欺骗率(no_fool)四模式稳定 100%、题目区分度(strict_order)注入标准答案后从 73% 升到 82%**；但样本仅 11 题、差异在噪声内（置信区间重叠），无法据此外推「主增益来自金标准注入」，需扩大/加难基准才能分离两旋钮贡献。

> 拆分版（如需按任务写多条简历 bullet，均按「痛点 → 思路 → 从多少到多少」）：
> - **追问聚焦（用户侧）**：针对「深挖追问总问泛泛、抓不住我刚答岔的薄弱点」，采取「贯通 decide_next.guidance → generate_dynamic_question 管道，让 deep_dive 随上一轮回答动态出同主题换角度的题」，结果 0 回归、追问从硬编码单句变为按回答动态生成。
> - **判分可信（用户侧）**：针对「判分不知道准不准、不敢信」，采取「把判卷拆成"量规 prompt"与"标准答案注入"两个正交维度做四模式消融」，结果 题目区分度(strict_order)注入标准答案后从 73% 升到 82%、no_fool 四模式稳定 100%；但样本仅 11 题、差异在噪声内（置信区间重叠），无法定论主增益来源，需扩大基准验证。
> - **模块清场（工程侧）**：针对「模拟面试长期停在单文件脚本、引用分裂难演进」，采取「删 scripts 壳 + 迁移 6 处引用 + 新增 `src/mock/__main__.py` 入口 + `__init__.chat_json` re-export」，结果 49 passed / 2.08s / 0 活引用残留。
