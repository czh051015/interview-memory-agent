# 25 · 开发计划书：评分语义匹配层（治中间态 fuzzy 漏判）

> 配套 docs/24（标准答案文字解析 + Trace）、benchmark/medium 中间态样本、run_evals 8 项回归体系。
> 背景实证：medium 档基线已锚定（run `20260831_220343`）——**fuzzy 漏判率 75%、nosource 假阳性率 100%**。
> 本文只做「治 fuzzy」的语义匹配层；「治 nosource」的材料结合度检查列为 Next（另一维度）。

---

## 0. 一句话

在评分链路的「关键词硬匹配」之后补一层 **embedding 语义匹配**：关键词没中的采分点，若与作答语义足够接近（本地向量相似度过阈值）也算命中——目标是让"跨城公交≈城际公交"这种同义改写不再漏判。

## 1. 背景与目标

**实证数据**（medium 档，人工按真实阅卷规则标 expected_hit_ids）：

| 中间态 | 当前表现 | 根因 |
|---|---|---|
| fuzzy（表达模糊/同义改写） | **漏判率 75%**（21/28 点该给分没给） | 硬匹配 `any(kw in answer)` 对同义改写脆弱 |
| nosource（自创/没结合材料） | **假阳性率 100%**（13/13 点不该给却给） | 缺"材料结合度"维度（≠本次范围） |

**目标**：
1. fuzzy 漏判率明显下降（75% → 目标 ≤40%，以校准结果为准）
2. **no_fool 守住 1.0**（语义层绝不能把跑题答判成命中）
3. nosource 假阳性率**不显著恶化**（监控项，恶化则回调阈值）
4. 保持确定性、可复现、0 LLM token（仍是"漏点识别传感器"）

**非目标（Non-goals）**：
- ❌ 不做材料结合度检查（列 Next，是"答案 70% 源自材料"对应的另一维度）
- ❌ 不上 LLM 评判（边界点精判列 Later）
- ❌ 不追求精确分数（评分语义不变）

## 2. 现状

- 评分链路：`src/shenlun/score.py` `score_answer(answer, points, materials)` → 每点 `any(kw in answer)` 判定 → hit/miss + matched_text + material_source（0 token 确定性）
- 资源已具备：本地 Ollama `shaw/dmeta-embedding-zh`（768 维中文嵌入，用户记忆确认），Chroma 向量设施已有——**0 新依赖、0 LLM 成本**

## 3. 方案：两阶段命中判定

```
作答 text + 采分点集
        │
        ▼
[阶段1] 关键词硬匹配（现有 score_answer 逻辑，不动）
        ├─ 命中 → hit（matched_text 定位）
        └─ 未命中 → 进入阶段2
        ▼
[阶段2] 语义匹配（新增）：
   对每个未命中点 p：
     p 的 query 向量 = embed(point 名 + keywords 拼接)
     作答按句切分 → 每句向量 → 取 max cosine(p, 作答句)
     若 max ≥ 阈值 τ → 判命中（semantic hit）
     否则 → miss
```

**关键设计点**：
1. **embedding 选型**：`shaw/dmeta-embedding-zh`（本地，确定性，0 token）。备选 `bge-m3`（SiliconFlow API，仅当本地质量差时评估）
2. **匹配粒度**：采分点（点名称 + keywords）vs **作答分句**取 max——比 vs 作答全文更准（全文平均会被稀释），也比 vs 关键词逐个更稳
3. **阈值 τ 不拍脑袋**：在 medium 样本上扫 τ∈[0.55, 0.90]，选"fuzzy 漏判率最低 + nosource 假阳性可控 + no_fool=1.0"的折中点，写入配置
4. **可解释性（trace）**：semantic hit 记录 `semantic_score`（如 0.82）和命中的作答句子——开发者可见"为什么判命中"，延续 24 号的 trace 基因
5. **确定性**：embedding 模型版本固定，同输入必同输出，可复现

## 4. 后端改动（`src/shenlun/score.py` + 新配置）

| 改动 | 说明 |
|---|---|
| `embed_zh(texts) -> list[list[float]]` | 本地 dmeta 嵌入封装（首次调用初始化模型，后续复用） |
| `_semantic_match(point, answer_sents, τ) -> (bool, float, str)` | 未命中点的语义判定：返回 是否命中、相似度、命中的作答句 |
| `score_answer` 加 `use_semantic: bool = True, tau: float = 0.75` | 阶段2 开关 + 阈值（默认值待校准定） |
| hit 结果扩展 `matched_by: "kw" \| "semantic"`, `semantic_score: float \| None` | 命中来源可追踪（trace 用） |
| 配置：`tau` 放配置常量（校准后写死） | 避免散落魔法数 |

**兼容**：`score_answer` 返回结构向后兼容（新增字段可选），`run_evals` / medium_eval / 前端均不破坏。

## 5. 校准与验证

1. **阈值校准脚本**（新 `eval/calibrate_tau.py`）：在 medium 样本上扫 τ，输出曲线表：
   `τ | fuzzy 漏判率 | nosource 假阳性率 | bad(跑题) 误判数 | 判定`
   取折中 τ 写入配置
2. **全量回归**：`python scripts/run_evals.py` → 8 项 headline 对比（重点看 fuzzy 漏判率 ↓、nosource 假阳性率变化、**no_fool 守住 1.0**、discrimination 变化）
3. **边界**：
   - bad（跑题）在 τ 下不能误判（= no_fool 红线，校准曲线里强制约束）
   - nosource 若在最优 τ 下假阳性仍 ≥80% → 记录为已知限制，②材料结合度评估加速
4. 回归跑两次确认稳定性（±0.01 内视为稳定）

## 6. 工作量拆解

| 任务 | 复杂度 | 依赖 |
|---|---|---|
| `embed_zh` 封装（dmeta 本地调用） | 低 | 无 |
| `_semantic_match` + `score_answer` 扩展 | 中 | embed_zh |
| 校准脚本 `calibrate_tau.py` + 选 τ | 中 | medium 样本（已有） |
| trace 标注（matched_by / semantic_score） | 低 | score 扩展 |
| 全量回归验证 | 低 | 全部 |

## 7. 风险与边界

| 风险 | 应对 |
|---|---|
| nosource 假阳性恶化（语义相似把自创判命中） | 校准曲线监控；恶化明显则保守取 τ；预期管理：语义层治 fuzzy 不治 nosource |
| no_fool 失守 | 校准强约束：bad 误判=0 才可选 τ；回归必查 |
| 本地 embedding 首载慢 / 内存 | 模型常驻复用；dmeta 768 维轻量（16G 内存机器可用） |
| 切句质量影响 max 相似度 | 简单标点切句即可（中文句号/分号/逗号），不引入 NLP 依赖 |

## 8. 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 评测先行 | medium 基线已锚定（fuzzy 75%/nosource 100%） | 先量化再改，改完有对照 |
| 语义层 | 本地 dmeta embedding，两阶段判定 | 0 LLM token、确定性、可复现，保住"传感器"定位 |
| 阈值 | 校准曲线定，不拍脑袋 | 平衡漏判↓ vs 假阳性↑ vs no_fool |
| 治序 | 先 fuzzy（语义层）→ 后 nosource（材料结合度，Next） | 语义层快、确定性胜利；材料结合度改评分语义，慢 |
| 面试叙事 | "两档极端 + 三类中间态 + 8 项回归"评估体系 | 见 §背景，完整可信度故事 |
